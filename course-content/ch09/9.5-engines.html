Engines on AKS & zero-trust practice

You'll be able to choose a network policy engine on AKS, know what each can enforce, and organise policies so they stay correct as the app changes.

1. No engine, no enforcement

The API server stores NetworkPolicies, but it doesn't enforce them. A policy engine in the dataplane does.

On a cluster without one, every policy is accepted and has no effect. There's no error and no warning.

Contoso applies default-deny and the matrix in testing still shows every flow open. The YAML is correct and kubectl get netpol lists it. Why?

  1. Policies take an hour to apply Enforcement is near-instant when an engine is present.
  2. The cluster was created without a network policy engine, so nothing enforces policies
  3. Default-deny only works in kube-system The opposite: don't use it there.
  4. NetworkPolicies need Istio They're a core Kubernetes API, enforced by the CNI dataplane.
Check with az aks show --query networkProfile.networkPolicy. Always test policies with real traffic, not just kubectl get.

2. Engines on AKS

EngineHow you get itNotes
Cilium (recommended)--network-dataplane cilium (Azure CNI powered by Cilium)eBPF; scales well; L7 and FQDN policies with Advanced Container Networking Services
Calico--network-policy calicoMature; its own extended policy CRDs
Azure Network Policy Manager--network-policy azureBeing retired. Don't choose it for new clusters; plan migration for existing ones

The engine is chosen when the cluster is created. Changing it later is limited and disruptive, so decide up front, in IaC (Chapters 12–13).

3. Beyond L3/L4

Standard NetworkPolicy works on IPs and ports (layers 3 and 4). With Cilium and Advanced Container Networking Services you can also write:

  • FQDN egress rules (lesson 9.4);
  • L7 HTTP rules, for example "web may only GET /api/orders/*";
  • flow logs and network observability, to see which flows exist before you lock them down.

4. Requirement → capability

Match each requirement to what provides it.

Deny all traffic between namespaces except listed flowsStandard NetworkPolicy (any engine)
Allow egress only to api.payments-provider.exampleCilium FQDN policy (ACNS) or Azure Firewall
Only allow GET requests on /api/ordersCilium L7 policy (or a service mesh)
See which pods talk to which before writing policiesFlow logs / network observability
Encrypt and authenticate pod-to-pod trafficA service mesh with mTLS (or Cilium transparent encryption)
Standard NetworkPolicy covers most needs. Add the advanced features where a requirement demands them.

5. Where policies live in the repo

Contoso's layout:

  • k8s/namespaces/: the platform template: Namespace, quota, LimitRange, default-deny, allow-dns.
  • k8s/policies/: the app's own allow policies (its ingress from callers, its egress to dependencies), deployed with the app.

In Chapter 10, default-deny goes into the Kustomize base, so every overlay (dev, prod) gets it automatically.

6. Policy changes are code changes

  • Review policies in PRs, like any other code.
  • Test them in CI: the course's netpol-eval grader is the same idea as tools that compute a connectivity matrix from YAML.
  • Test them in a real cluster after deploy, with a smoke test that checks one allowed and one denied flow.

7. Rolling out to an existing app

  1. Turn on flow logs and watch real traffic for a few days.
  2. Write allow policies for the observed flows.
  3. Apply ingress default-deny first; watch for drops.
  4. Then egress default-deny, with DNS allowed from the start.

8. Cluster-wide policies

NetworkPolicies are namespaced, and namespace owners can add allows. For guardrails that namespace owners can't override, such as "nothing may reach the metadata endpoint", there are cluster-scoped options:

  • engine-specific policies (CiliumClusterwideNetworkPolicy, Calico GlobalNetworkPolicy);
  • the upstream AdminNetworkPolicy API, as engines adopt it.

Engines & practice, sorted

  • No engine = no enforcement; always test with real traffic.
  • On AKS choose Cilium (recommended) or Calico at creation; Azure NPM is retiring.
  • FQDN and L7 policies, plus flow logs, come with Cilium + ACNS.
  • Default-deny and DNS in the namespace template; app allow-lists ship with the app.
