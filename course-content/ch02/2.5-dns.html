DNS & service discovery

You'll be able to build the DNS name of any Service, know when the short name works, and write connection strings that work across namespaces.

1. Every Service gets a DNS name

The cluster runs its own DNS server, CoreDNS, in kube-system. Every pod is configured to use it.

For every Service, CoreDNS answers this name with the Service's ClusterIP:

<service>.<namespace>.svc.cluster.local

So orders-api in namespace orders is orders-api.orders.svc.cluster.local.

Windows/IIS admin
Like an internal AD DNS zone that registers every Service automatically. cluster.local is the zone; namespaces are like subdomains.
Linux admin
Look at a pod's /etc/resolv.conf: the nameserver is CoreDNS's ClusterIP, with search domains for the namespace.
Developer (Compose)
Compose resolves service names on one network. Kubernetes does the same, scoped by namespace.
Other clouds
Identical on EKS and GKE. AKS can also forward to Azure private DNS zones (Chapter 5).

2. Short names and search domains

You don't have to type the full name. Each pod's /etc/resolv.conf has search domains for its own namespace, so short names get expanded:

  • From a pod in orders, orders-api resolves (expanded to orders-api.orders.svc.cluster.local).
  • From a pod in any namespace, orders-api.orders resolves.
  • From a pod in another namespace, plain orders-api looks in that namespace and fails.
$ kubectl exec -n orders web-6c8f9d7b5-h4j2k -- cat /etc/resolv.conf
search orders.svc.cluster.local svc.cluster.local cluster.local
nameserver 10.0.0.10
options ndots:5

3. Calling across namespaces

Contoso moves the web frontend into its own namespace, web. orders-api stays in orders.

Which base URL should web (namespace web) use to reach the orders-api Service (port 80, namespace orders)?

  1. http://orders-api From namespace web, this looks up orders-api.web.svc.cluster.local, which doesn't exist.
  2. http://orders-api.orders (or the full http://orders-api.orders.svc.cluster.local)
  3. http://orders.orders-api The order is service first, then namespace.
  4. http://10.244.1.12:8080 That's one pod's IP; it changes on every restart.
Across namespaces, always include the namespace. Many teams use the full name in configuration to make it explicit.

4. Ports aren't in DNS

DNS returns an IP address, not a port. The client must use the Service's port (80 here). orders-api.orders:8080 would fail, because 8080 is the pod's port, not the Service's.

For a named port, the SRV record _http._tcp.orders-api.orders.svc.cluster.local does carry the port, but few apps use it.

5. Write the connection setting

The web Deployment (namespace web) reads the API's base URL from an environment variable. Complete it.

env:
  - name: ORDERS_API_URL
    value: "http://?"
  • orders-api.orders.svc.cluster.local:80
  • orders-api:80 Only works from inside the orders namespace.
  • orders-api.orders.svc.cluster.local:8080 8080 is the container port; the Service listens on 80.
  • orders-api.svc.cluster.local:80 The namespace is missing.
Service name, namespace, svc.cluster.local, and the Service's port.

6. Testing DNS from inside the cluster

Start a throwaway pod with DNS tools and query from there. The --rm flag deletes the pod when you exit.

$ kubectl run tmp -n web --rm -it --image=busybox:1.36 --restart=Never -- nslookup orders-api.orders
Server:    10.0.0.10
Address:   10.0.0.10:53

Name:      orders-api.orders.svc.cluster.local
Address:   10.0.142.17
pod "tmp" deleted

7. When DNS isn't the problem

  • If the name resolves but connections fail, check the Service's endpoints (lesson 2.4), its targetPort, and network policies (Chapter 9).
  • If the name doesn't resolve, check the spelling, the namespace, and whether CoreDNS pods are running: kubectl get pods -n kube-system -l k8s-app=kube-dns.
  • External names, such as contosoacr.azurecr.io, are forwarded by CoreDNS to the VNet's DNS. Chapter 5 covers private zones.

DNS, sorted

  • <svc>.<ns>.svc.cluster.local resolves to the Service's ClusterIP.
  • The short name works only within the same namespace; across namespaces use at least svc.ns.
  • DNS gives the IP; use the Service's port, not the container's.
  • Test with a throwaway busybox pod and nslookup.
