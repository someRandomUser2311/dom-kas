Storage

You'll be able to request persistent storage with a PVC, pick a StorageClass and access mode, predict what happens to the data when things are deleted, and know when a StatefulSet is needed.

1. Containers forget

A container's filesystem disappears with the container (lesson 1.1). Pods get rescheduled to other nodes. So anything that must survive needs storage that lives outside the pod.

orders-api itself is stateless; its data lives in a managed database. But Contoso also runs a small queue that needs a disk, so let's learn how.

2. Volumes inside a pod

A volume is declared in the pod spec and mounted into containers. Some volume types live only as long as the pod:

  • emptyDir: scratch space shared by the pod's containers, deleted with the pod.
  • configMap and secret: config as files (Chapter 2).

For data that outlives pods, the volume points to a PersistentVolumeClaim.

3. PV, PVC and StorageClass

  • PersistentVolumeClaim (PVC): your request, for example "10 GiB, single-writer, premium". It belongs to a namespace.
  • PersistentVolume (PV): an actual piece of storage, such as an Azure managed disk. It's cluster-wide.
  • StorageClass: a template for creating PVs on demand. It names the CSI driver and its parameters (disk SKU, reclaim policy, binding mode).

With dynamic provisioning, creating a PVC causes the CSI driver to create a matching disk and PV automatically.

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: queue-data
  namespace: orders
spec:
  accessModes: [ReadWriteOnce]
  storageClassName: managed-csi-premium
  resources:
    requests:
      storage: 32Gi
volumes:
  - name: data
    persistentVolumeClaim:
      claimName: queue-data

4. Access modes

  • ReadWriteOnce (RWO): mounted read-write by one node at a time. Block storage such as Azure Disk.
  • ReadWriteOncePod (RWOP): one pod only. That's stricter still.
  • ReadOnlyMany (ROX): many nodes, read-only.
  • ReadWriteMany (RWX): many nodes read-write at once. File shares such as Azure Files (SMB/NFS) or Azure NetApp Files.

Match the need to the storage on AKS.

A database's data directory, one replicaAzure Disk (RWO)
Uploaded images shared by 5 web pods on different nodesAzure Files (RWX)
Scratch space for one pod's two containersemptyDir
A disk that must never be mounted by two pods, even on one nodeAzure Disk with ReadWriteOncePod
Disks are fast and single-writer; file shares are shared but slower. Pick by the access pattern.

5. One disk, many replicas?

A Deployment with 3 replicas mounts one RWO Azure Disk PVC. The pods are spread across 3 nodes. What happens?

  1. All 3 share the disk RWO allows only one node to attach it.
  2. The pod on the node that has the disk runs; the others are stuck in ContainerCreating with a "Multi-Attach error"
  3. Kubernetes creates 3 disks automatically Only StatefulSet volumeClaimTemplates do that.
  4. The PVC is rejected The PVC is fine; the problem appears when pods try to mount it.
For per-replica disks, use a StatefulSet. For shared data, use RWX (Azure Files). Better still, keep the app stateless and put state in a managed service.

6. AKS storage classes

AKS ships these StorageClasses (CSI drivers are on by default):

  • managed-csi (the default): Standard SSD.
  • managed-csi-premium: Premium SSD.
  • azurefile-csi and azurefile-csi-premium: Azure Files.

The disk classes use volumeBindingMode: WaitForFirstConsumer. The disk is only created once a pod is scheduled, so it lands in that pod's zone.

A locally redundant (LRS) disk is zonal: a pod using it can only run in that zone. A zone-redundant (ZRS) disk SKU can attach from any zone.

$ kubectl get storageclass

azurefile-csi-premium   file.csi.azure.com   Delete          Immediate              true
managed-csi (default)   disk.csi.azure.com   Delete          WaitForFirstConsumer   true
managed-csi-premium     disk.csi.azure.com   Delete          WaitForFirstConsumer   true

7. Reclaim policy: what happens to the data

When a PVC is deleted, its PV's reclaim policy decides the disk's fate:

  • Delete (the default for AKS classes): the Azure disk is deleted too.
  • Retain: the disk is kept, and an admin must clean up or reuse it manually.

For important data, use a class with Retain, and back up with snapshots or Azure Backup for AKS.

You run kubectl delete namespace orders. The queue-data PVC used managed-csi-premium. What happens to the queue's data?

  1. Kept in Azure as an orphaned disk Only with the Retain policy.
  2. The PVC, the PV and the Azure disk are all deleted, and the data is gone
  3. The namespace can't be deleted while a PVC exists Namespace deletion removes everything in it.
  4. The disk is moved to the default namespace PVs don't move between namespaces like that.
Deleting a namespace is one of the easiest ways to lose data on Kubernetes. Use Retain for data you care about, protect production namespaces with RBAC, and take backups.

8. StatefulSets: a disk per replica

A StatefulSet gives each replica:

  • a stable name (queue-0, queue-1);
  • a stable DNS name through a headless Service;
  • its own PVC, made from volumeClaimTemplates.

Pods start and stop in order. If queue-1 is rescheduled, it reattaches its own disk.

apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: queue
spec:
  serviceName: queue
  replicas: 3
  selector:
    matchLabels: { app: queue }
  template:
    metadata:
      labels: { app: queue }
    spec:
      containers:
        - name: queue
          image: contosoacr.azurecr.io/queue:2.1.0
          volumeMounts:
            - { name: data, mountPath: /var/lib/queue }
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        storageClassName: managed-csi-premium
        resources:
          requests:
            storage: 32Gi

9. Should you run databases on AKS?

You can, with StatefulSets and operators. For most teams, a managed service is the better choice: Azure Database for PostgreSQL, Azure SQL or Cosmos DB. Backups, patching, failover and zone redundancy are then someone else's job.

That's what Contoso does for its orders database. Keep AKS for the stateless parts.

10. Growing a volume

If the class has allowVolumeExpansion: true, increase spec.resources.requests.storage on the PVC and apply. Azure Disk can be expanded online, while it's in use, for most disk types.

You can't shrink a volume.

Storage, sorted

  • PVC = request; PV = actual storage; StorageClass = how to create it on demand.
  • RWO = one node (Azure Disk); RWX = many nodes (Azure Files).
  • AKS disk classes wait for the first pod, so the disk lands in its zone; LRS disks are zonal.
  • Reclaim Delete removes the disk with the PVC; use Retain and backups for real data.
  • StatefulSets give each replica its own disk; prefer managed databases.
