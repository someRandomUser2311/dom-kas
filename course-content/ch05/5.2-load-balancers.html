Services meet Azure

You'll be able to explain what AKS builds in Azure when you create a LoadBalancer Service, make it internal or give it a static IP, and know when to stop creating them.

1. From YAML to an Azure Load Balancer

When you create a Service with type: LoadBalancer, the cloud-controller-manager (Azure's side of the control plane) sees it and configures the cluster's Azure Load Balancer. It:

  • adds a frontend IP (a new public IP resource);
  • adds a load-balancing rule for the Service's port;
  • adds a health probe;
  • points them all at the node pool's VMSS.

Then it writes the IP into the Service's status.

A split view. The left shows the Service YAML; the right shows the Azure resources in the node resource group. Applying the YAML animates a public IP kubernetes-a1b2c3…, a frontend IP configuration, a rule TCP 80 and a probe appearing on the kubernetes load balancer. Deleting the Service removes them. Toggling the internal annotation moves the frontend to kubernetes-internal with a VNet IP.

2. Watch it happen

$ kubectl apply -f web-svc.yaml
service/web created
$ kubectl get svc web -n web -w
NAME   TYPE           CLUSTER-IP    EXTERNAL-IP   PORT(S)        AGE
web    LoadBalancer   172.16.88.3   <pending>     80:31452/TCP   3s
web    LoadBalancer   172.16.88.3   20.50.12.34   80:31452/TCP   41s

While EXTERNAL-IP is <pending>, Azure resources are being created. If it stays pending, check the Service's events. The usual causes are a permission error for the cluster identity, or quota.

3. Internal load balancers

Not everything should be on the internet. Add one annotation and the Service gets a private IP from your VNet, on a separate kubernetes-internal load balancer. Other VNets, VPN users and on-premises networks can reach it; the internet can't.

A second annotation picks which subnet the IP comes from.

Make this Service internal.

apiVersion: v1
kind: Service
metadata:
  name: orders-admin
  namespace: orders
  annotations:
    ?: "true"
    service.beta.kubernetes.io/azure-load-balancer-internal-subnet: snet-ingress
spec:
  type: LoadBalancer
  selector: { app: orders-admin }
  ports:
    - port: 443
      targetPort: 8443
  • service.beta.kubernetes.io/azure-load-balancer-internal
  • service.beta.kubernetes.io/azure-internal Close, but not the exact name; unknown annotations are silently ignored, so you'd get a public IP.
  • kubernetes.io/internal-lb Not an Azure annotation.
  • networking.azure.com/private Doesn't exist.
The exact key matters: a typo in an annotation doesn't cause an error, it just creates a public IP. Always check EXTERNAL-IP after applying.

4. Static IPs

By default the public IP is created and deleted with the Service. Delete and recreate the Service, and the address changes, breaking DNS records and firewall rules that point at it.

For a stable address:

  1. Create a Standard SKU public IP yourself (or with IaC).
  2. Give the cluster identity Network Contributor on its resource group.
  3. Reference it by name with an annotation.
annotations:
  service.beta.kubernetes.io/azure-pip-name: pip-orders-web
  service.beta.kubernetes.io/azure-load-balancer-resource-group: rg-orders-net

spec.loadBalancerIP also exists, but it's deprecated in Kubernetes. Prefer the annotation.

5. Keeping the client's IP

By default, traffic may arrive at any node and be forwarded to a pod on another node. The pod then sees the node's IP, not the client's.

externalTrafficPolicy: Local sends traffic only to nodes that have a ready pod. That keeps the client's source IP, at the cost of potentially uneven load.

For HTTP apps, a gateway usually passes the client IP in a header anyway (Chapter 8).

6. The problem with many LoadBalancer Services

Contoso has 10 HTTP services and gives each one a public LoadBalancer Service. What's the main downside, compared with one gateway in front of them all?

  1. It doesn't work: AKS allows only one LoadBalancer Service You can have many.
  2. 10 public IPs to pay for, secure, certify and put in DNS, with no shared TLS, routing or WAF
  3. LoadBalancer Services can't do HTTPS They pass TCP through, so the app can terminate TLS, but each one must manage its own certificate.
  4. It's cheaper Each public IP and rule costs money.
For HTTP, expose one entry point (a Gateway or Ingress, Chapter 8) that routes by host and path to ClusterIP Services. Keep LoadBalancer Services for non-HTTP TCP/UDP or the gateway itself.

7. Permissions: why <pending> lasts forever

EXTERNAL-IP stays <pending>. Why?

$ kubectl describe svc web -n web | tail -4
Events:
  Type     Reason                  From                Message
  Warning  SyncLoadBalancerFailed  service-controller  Error syncing load balancer: failed to ensure load balancer:
           ... does not have authorization to perform action 'Microsoft.Network/publicIPAddresses/read'
           over scope '/subscriptions/…/resourceGroups/rg-orders-net/providers/Microsoft.Network/publicIPAddresses/pip-orders-web'
  1. The Service selector is wrong That gives no endpoints, but the IP would still be assigned.
  2. The cluster identity lacks permission on the resource group holding the static public IP
  3. The cluster is on the Free tier Free clusters can create load balancers.
  4. The pods aren't ready IP assignment doesn't wait for pods.
Grant the cluster (control-plane) identity Network Contributor on rg-orders-net. The next lessons cover which identity does what.

8. A friendly DNS name

The annotation service.beta.kubernetes.io/azure-dns-label-name: contoso-orders-web gives the public IP a name like contoso-orders-web.westeurope.cloudapp.azure.com. That's handy for demos. In production, use your own domain with Azure DNS.

9. Outbound uses the same load balancer

The same Azure Load Balancer also handles outbound traffic from nodes by default, using its own public IP. The next lesson covers why you might change that.

Services in Azure, sorted

  • type: LoadBalancer → the cloud-controller-manager adds a frontend IP, rule and probe to the Azure LB.
  • Internal: service.beta.kubernetes.io/azure-load-balancer-internal: "true" (+ subnet).
  • Static IP: a pre-created Standard public IP + azure-pip-name + Network Contributor for the cluster identity.
  • <pending> forever → read the Service's events.
  • Many HTTP services → one gateway (Chapter 8), not many public IPs.
