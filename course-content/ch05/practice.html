Write lab: workload identity manifests

Task values: managed identity client ID 6c1f2a9e-0000-4b1d-9c55-1a2b3c4d5e6f; federated credential subject system:serviceaccount:orders:orders-api. Write serviceaccount.yaml and update deployment.yaml so orders-api can read Key Vault. Graded by manifest-lint and cross-ref.

  • A ServiceAccount exists with the azure.workload.identity/client-id annotation set to the given client ID.
  • The Deployment's serviceAccountName references that ServiceAccount.
  • The pod template has the label azure.workload.identity/use: "true" (a quoted string).
  • The ServiceAccount's namespace and name match the federated credential subject.
  • No client secret or credentials anywhere (no AZURE_CLIENT_SECRET, no Secret holding credentials).
  • AZURE_CLIENT_ID isn't hard-coded in env (the webhook injects it).
Reference solution 
apiVersion: v1
kind: ServiceAccount
metadata:
  name: orders-api
  namespace: orders
  annotations:
    azure.workload.identity/client-id: "6c1f2a9e-0000-4b1d-9c55-1a2b3c4d5e6f"
---
# deployment.yaml (template excerpt)
  template:
    metadata:
      labels:
        app: orders-api
        azure.workload.identity/use: "true"
    spec:
      serviceAccountName: orders-api

5.2 LoadBalancer without a cloud.

kubectl create deployment web --image=localhost:5001/orders-api:1.0.0
kubectl expose deployment web --type=LoadBalancer --port=80 --target-port=8080
kubectl get svc web

Expected: EXTERNAL-IP <pending>, forever. kind has no cloud-controller-manager to create a load balancer. On AKS, this is exactly the step Azure performs.

Cleanup: kubectl delete deploy,svc web

5.6 Look inside a ServiceAccount token.

kubectl create ns orders; kubectl create sa orders-api -n orders
TOKEN=$(kubectl create token orders-api -n orders --audience api://AzureADTokenExchange)
echo "$TOKEN" | cut -d. -f2 | tr '_-' '/+' | base64 -d 2>/dev/null; echo

Expected: JSON with "aud":["api://AzureADTokenExchange"], "iss":"https://kubernetes.default.svc.cluster.local" and "sub":"system:serviceaccount:orders:orders-api". On AKS, iss is the public OIDC issuer URL, and Entra ID checks iss + sub against the federated credential.

Cleanup: kubectl delete ns orders
