Write lab: Gateway + HTTPRoutes with TLS

Brief: Write k8s/gateway/gateway.yaml, orders-route.yaml and web-route.yaml:

  • A Gateway shop-gateway in gateway-infra (class azure-alb-external) serves shop.contoso.example on HTTPS and redirects HTTP.
  • /api goes to orders-api:80 (namespace orders); everything else goes to web:80 (namespace web).
  • Given: the Services exist as in Chapter 2, and namespaces orders and web carry shop-routes: allowed.

Graded by manifest-lint and cross-ref.

  • All resources use gateway.networking.k8s.io/v1.
  • The public listener uses protocol: HTTPS on 443 with tls.mode: Terminate and a certificateRefs entry.
  • No TLS private key in any file (no Secret with tls.key data).
  • Each HTTPRoute's parentRefs matches the Gateway's name and namespace.
  • allowedRoutes admits the route namespaces (selector on shop-routes: allowed).
  • Route hostnames match the listener's hostname.
  • Every backendRefs entry names an existing Service and port in the route's namespace.
  • HTTP (port 80) is only used for a RequestRedirect to HTTPS.
Reference solution

The Gateway from lesson 8.4, step 3 (with hostname: shop.contoso.example and an added http listener), the two routes from 8.4 steps 4–5, and the redirect route from 8.6, step 6. The certificate comes from cert-manager through the Gateway annotation.

Walkthrough: quota rejection → fix → expose → curl

  1. Apply the namespace template (quota, no LimitRange) and deploy orders-worker; read the ReplicaSet's "must specify requests" event.
  2. Add the LimitRange; the pods start.
  3. Apply the Gateway and HTTPRoutes; kubectl get gateway shows an address.
  4. curl https://shop.contoso.example/api/healthz and curl -I http://shop.contoso.example/ (a 301 to HTTPS).

Try it locally

8.1–8.2 Quota rejection.

kubectl create ns quota-demo
kubectl create quota q -n quota-demo --hard=requests.cpu=1,requests.memory=1Gi
kubectl create deployment nr -n quota-demo --image=localhost:5001/orders-api:1.0.0
kubectl describe rs -n quota-demo | grep -m1 "must specify"

Expected: "failed quota: q: must specify requests.cpu…".

Cleanup: kubectl delete ns quota-demo

8.3 An Ingress. Install the lab's maintained Ingress controller (pinned in lab/addons/ingress.sh), then:

./lab/addons/ingress.sh
kubectl apply -f lab/examples/ch08/shop-ingress.yaml     # web + orders-api + Ingress
kubectl port-forward -n ingress svc/ingress-controller 8080:80 &
curl -s -H "Host: shop.local" localhost:8080/api/healthz; curl -s -H "Host: shop.local" localhost:8080/ | head -1

Expected: ok from orders-api, then the web page's first line.

Cleanup: kill %1; kubectl delete -f lab/examples/ch08/shop-ingress.yaml
