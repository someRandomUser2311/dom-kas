Ingress options on AKS

You'll be able to compare the managed and self-managed ways to get HTTP traffic into AKS, and pick one for a given set of requirements.

1. Someone has to run the proxy

Ingress and Gateway resources need a controller. On AKS you can let Azure manage it, or install and run one yourself. Managed options cost less effort and are patched for you; self-managed options give you more choice.

This area changes quickly. Check the current docs before committing.

2. The application routing add-on

A one-command add-on (az aks approuting enable) that installs and manages an NGINX-based ingress controller inside the cluster, with IngressClass webapprouting.kubernetes.azure.com.

It integrates with Azure DNS (automatic records) and Key Vault certificates, and AKS keeps it updated.

Microsoft is moving the add-on toward the Gateway API. Check which mode your cluster version supports.

az aks approuting enable -g rg-orders-dev -n aks-orders-dev
kubectl get ingressclass
# NAME                                 CONTROLLER
# webapprouting.kubernetes.azure.com   webapprouting.kubernetes.azure.com/nginx

3. Application Gateway for Containers

Application Gateway for Containers (AGC) is an Azure-managed layer-7 load balancer that runs outside the cluster. An in-cluster ALB controller programs it from Gateway API resources (GatewayClass azure-alb-external) or Ingress resources.

Because the data plane is outside the cluster, there are no proxy pods to scale. It supports traffic splitting, mutual TLS and a web application firewall.

It's the successor to the older AGIC (Application Gateway Ingress Controller).

4. The Istio-based service mesh add-on

If you enable AKS's Istio add-on for mesh features such as mTLS between services, traffic policies and telemetry, it can also provide ingress gateways, and supports the Gateway API.

It's a lot of machinery if you only need ingress, but natural if you want a mesh anyway.

5. Self-managed controllers

You can install any controller with Helm, for example Envoy Gateway, Traefik, HAProxy, Contour, or Cilium's Gateway API support. You get full control and portability.

You also own upgrades, scaling, high availability and every security patch.

6. The community ingress-nginx retirement

The widely used community ingress-nginx project (kubernetes/ingress-nginx) has been retired. After its end-of-maintenance date in March 2026 it gets no further releases or security fixes. Existing installs keep working, but they're unpatched.

What it means:

  • Don't install it on new clusters.
  • Plan a migration for existing clusters, ideally to the Gateway API with a maintained implementation.
  • The AKS application routing add-on is built on NGINX but has its own Microsoft support timeline. Check it rather than assuming either way.

8. Scenarios

Contoso's security team requires a web application firewall in front of the shop, and wants the Gateway API with weighted canaries. The platform team is small. Which option fits best?

  1. Community ingress-nginx Retired, and has no WAF.
  2. Application Gateway for Containers
  3. The app routing add-on in Ingress mode There's no built-in WAF, and the Gateway API support is still emerging.
  4. A LoadBalancer Service per app No layer-7 features at all.
AGC is managed, supports the Gateway API (including weights) and can attach a WAF policy.

9. Which requirements does each meet?

A dev cluster needs: the cheapest possible setup, little to manage, HTTP routing for three internal apps, and automatic DNS records. Which options meet all of these?

  1. The application routing add-on
  2. Application Gateway for Containers It works, but it's a separate billed Azure resource. Not the cheapest.
  3. The Istio add-on A lot of machinery for three internal apps.
  4. Self-managed Envoy Gateway You'd run it, and DNS automation needs extra tooling such as external-dns.
The add-on integrates with Azure DNS and is managed for you, a good fit for simple and dev scenarios.

AKS ingress options, sorted

  • App routing add-on: managed NGINX in-cluster, simplest, with DNS and Key Vault integration.
  • Application Gateway for Containers: managed L7 outside the cluster, Gateway API, WAF.
  • Istio add-on: if you want a mesh anyway.
  • Self-managed: full control, full responsibility.
  • Community ingress-nginx is retired; move to the Gateway API.
