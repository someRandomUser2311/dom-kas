Write lab: deploy-private.sh

Brief: Write deploy-private.sh to apply k8s/base/ to namespace orders on the private cluster aks-orders-prod in rg-orders-prod, using az aks command invoke. Graded by cli-spec.

  • The script starts with set -euo pipefail.
  • It uses az aks command invoke with resource group rg-orders-prod and name aks-orders-prod.
  • --command runs kubectl apply targeting namespace orders.
  • --file attaches the manifests (a folder or files), and the paths in the command match.
  • The cluster stays private: no az aks update that enables a public endpoint or sets --api-server-authorized-ip-ranges.
  • No credentials hard-coded (no client secrets, passwords or tokens; no az login -p).
Reference solution

See lesson 6.6, step 7.

Walkthrough: public → private → fixed

  1. az acr build pushes orders-api:1.5.0; az aks update --attach-acr; az aks check-acr.
  2. Deploy to the public dev cluster from a pipeline with KubernetesManifest@1.
  3. Run the same pipeline against private prod on a hosted agent: it fails at DNS.
  4. Switch the job to the Managed DevOps Pool in the peered VNet with the hub DNS resolver: it succeeds.
  5. Emergency path: az aks command invoke … --command "kubectl rollout status deploy/orders-api -n orders".

Try it locally

6.1 Push and run from the local registry.

docker tag localhost:5001/orders-api:1.0.0 localhost:5001/orders/orders-api:1.0.1
docker push localhost:5001/orders/orders-api:1.0.1
kubectl create deployment oa --image=localhost:5001/orders/orders-api:1.0.1
kubectl get pods -l app=oa

Expected: the pod runs, pulled from the local registry.

Cleanup: kubectl delete deploy oa

On AKS: pulls are authenticated with the kubelet identity's AcrPull role.

6.2 Read pull errors.

kubectl run bad-tag --image=localhost:5001/orders-api:9.9.9
kubectl run bad-host --image=contosoacr.azurecr.io/orders-api:1.4.2
sleep 20; kubectl describe pod bad-tag | grep -m1 Failed; kubectl describe pod bad-host | grep -m1 Failed

Expected: bad-tag → "not found"; bad-host → "no such host" or an authorisation error, depending on your network.

Cleanup: kubectl delete pod bad-tag bad-host
