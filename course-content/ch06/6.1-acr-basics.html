ACR basics

You'll be able to create an Azure Container Registry, push and build images in it, and set it up without shared passwords.

1. Why a private registry?

Docker Hub is public by default, rate-limited, and outside your control. Contoso's images belong in a private registry:

  • in the same Azure region as the cluster, for fast pulls;
  • protected by Entra ID;
  • reachable privately from the VNet.

That's Azure Container Registry (ACR). It stores OCI images, Helm charts and other OCI artifacts.

Windows/IIS admin
Think of ACR as an internal file share for build outputs (the MSI or Web Deploy packages), versioned and access-controlled.
Linux admin
Like a private apt repository or an internal Harbor instance, managed by Azure.
Developer (Compose)
Instead of docker push yourname/app to Docker Hub, you push to contosoacr.azurecr.io/app.
Other clouds
ACR ≈ Amazon ECR ≈ Google Artifact Registry.

2. Names: login server, repository, tag

A registry called contosoacr has the login server contosoacr.azurecr.io. Registry names are globally unique, lowercase and alphanumeric only.

Inside, images are grouped into repositories. A repository name can include slashes, like orders/orders-api. Each image version is a tag and a digest (lesson 1.1).

Complete the image reference for tag 1.4.2 of orders-api in the registry contosoacr.

image: ?/orders-api:1.4.2
  • contosoacr.azurecr.io
  • contosoacr Without a domain, Docker assumes Docker Hub's docker.io/contosoacr.
  • contosoacr.azure.com ACR login servers end in .azurecr.io.
  • acr.contoso.com Only if you've configured a custom domain; the default is .azurecr.io.
Always use the full login server in image references.

3. SKUs

SKUHighlights
BasicLowest cost and storage; fine for learning
StandardMore storage and throughput; most production needs
PremiumAdds private endpoints, geo-replication, more throughput, and more governance features

You can move up a SKU at any time. Contoso uses Premium in production, because it needs private endpoints (lesson 6.3).

4. Create a registry

az acr create \
  --resource-group rg-orders-shared \
  --name contosoacr \
  --sku Premium \
  --admin-enabled false

One registry is usually shared by dev and prod clusters, in a shared resource group. The same image is then promoted from dev to prod, never rebuilt.

5. The admin user: keep it off

ACR has an optional admin user: one username and two passwords with full push and pull rights. It's off by default.

Turning it on is tempting for quick tests. Don't. Use Entra ID identities instead:

  • az acr login for people;
  • AcrPush for pipelines;
  • AcrPull for the AKS kubelet.

Why keep the ACR admin user disabled?

  1. It's slower Performance is the same.
  2. It's a single shared credential with full rights, so you can't tell who pushed what or limit it, and it has to be rotated by hand
  3. It only works with Docker Hub It's an ACR feature.
  4. It costs extra It's free, which is part of why it's tempting.
Individual identities give an audit trail and least privilege. An Azure Policy can deny registries with the admin user enabled.

6. Logging in and pushing

az acr login uses your az login session to get a short-lived registry token, then configures Docker with it. You need the AcrPush role (or Container Registry Repository Writer, where repository permissions are enabled).

az acr login --name contosoacr
docker build -t contosoacr.azurecr.io/orders-api:1.4.2 .
docker push contosoacr.azurecr.io/orders-api:1.4.2

You've built and tagged the image. Push orders-api version 1.4.2 to Contoso's registry.

docker push contosoacr.azurecr.io/orders-api:1.4.2

Also accepted: podman push with the same reference.

The reference's registry part tells Docker where to push.

7. Build in Azure: az acr build

ACR Tasks can build the image inside Azure. az acr build uploads your source folder, builds it from the Dockerfile, and pushes the result. No local Docker is needed.

It's handy for laptops without Docker and for pipelines. It can also run on a schedule, or when a base image updates.

$ az acr build --registry contosoacr --image orders-api:1.4.2 .
Packing source code into tar to upload...
Queued a build with ID: ca1
Step 1/12 : FROM golang:1.23 AS build
...
Successfully pushed image: contosoacr.azurecr.io/orders-api:1.4.2
Run ID: ca1 was successful after 1m12s

8. Browsing the registry

az acr repository list -n contosoacr -o table
az acr repository show-tags -n contosoacr --repository orders-api --orderby time_desc -o table
az acr manifest list-metadata -r contosoacr -n orders-api -o table   # digests, sizes, dates

9. Tags Contoso uses

  • An immutable version per build: the semantic version, or the build ID plus the commit SHA (1.4.2, 20261103.4-3f5a9c0). Never overwrite it.
  • No latest in manifests.
  • Deploy by tag and record the digest, or deploy by digest (Chapter 16).

Lock a tag against changes with az acr repository update --write-enabled false.

10. Helm charts live here too

ACR stores Helm charts as OCI artifacts: helm push orders-api-0.3.0.tgz oci://contosoacr.azurecr.io/helm. One registry then holds both images and charts (Chapter 10).

ACR, sorted

  • Login server <name>.azurecr.io; repositories, tags, digests.
  • Basic / Standard / Premium; Premium for private endpoints and geo-replication.
  • Admin user off; Entra ID identities with AcrPush and AcrPull.
  • az acr login + docker push, or az acr build in Azure.
  • Immutable version tags; no latest.
