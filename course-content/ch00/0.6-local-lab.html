Set up a local lab

You'll have a free, multi-node Kubernetes cluster running on your own machine, ready for the optional "Try it locally" boxes in later chapters. Nothing graded needs it.

1. Why a local cluster?

Every lesson and lab in this course works in the browser. A local cluster adds something the browser can't: real output and real errors, like a genuine CrashLoopBackOff or a real rollout.

We use kind (Kubernetes IN Docker). Each Kubernetes node is a container on your machine. It's free, it starts in about a minute, and you can delete it and start again at any time.

What it can't do: anything Azure-specific. It has:

  • no AKS features
  • no ACR authentication
  • no Entra ID sign-in
  • no Azure load balancers
  • no Azure DevOps

Each box tells you where local behaviour differs from AKS.

Windows/IIS admin
On Windows, run everything inside WSL2 (Ubuntu). Docker Desktop and Podman both integrate with it.
Linux admin
You can use Docker Engine or Podman directly; Docker Desktop isn't needed.
Developer (Compose)
If docker compose up works on your machine, kind will too.
Other clouds
Like minikube or k3d. We chose kind because its multi-node setup lets us fake availability zones.

2. What's in the course lab

lab/lab-up.sh creates a cluster called kq:

  • 1 control-plane node.
  • 3 worker nodes, labelled topology.kubernetes.io/zone = zone-1, zone-2 and zone-3. These stand in for availability zones in Chapter 3.
  • 1 "gpu" worker, labelled gpu=true and tainted gpu=true:NoSchedule, so ordinary pods stay off it. This is for the taints and tolerations box.
  • A local registry at localhost:5001. It stands in for ACR: you push images to it, and the cluster pulls from it.
  • metrics-server, so kubectl top and the autoscaler work.

Chapters that need more, such as a Gateway controller, network-policy enforcement or Kyverno, install it with a script in lab/addons/.

kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
name: kq
nodes:
  - role: control-plane
  - role: worker
    labels: { topology.kubernetes.io/zone: zone-1 }
  - role: worker
    labels: { topology.kubernetes.io/zone: zone-2 }
  - role: worker
    labels: { topology.kubernetes.io/zone: zone-3 }
  - role: worker
    labels: { gpu: "true", topology.kubernetes.io/zone: zone-1 }
    kubeadmConfigPatches:
      - |
        kind: JoinConfiguration
        nodeRegistration:
          taints:
            - key: gpu
              value: "true"
              effect: NoSchedule
containerdConfigPatches:
  - |
    [plugins."io.containerd.grpc.v1.cri".registry]
      config_path = "/etc/containerd/certs.d"

The last block tells each node's container runtime to look for registry settings in /etc/containerd/certs.d. lab-up.sh writes a file there that maps localhost:5001 to the registry container, which is the method in kind's own local-registry guide.

3. Install the tools

You need four tools. The exact versions the course is tested with are in lab/versions.env.

  • A container engine: Docker Desktop, Docker Engine (Linux), or Podman.
  • kind
  • kubectl
  • helm

Hardware: about 4 CPUs and 8 GB of RAM free. On a smaller machine, use the single-node lab (step 6).

Docker Desktop needs a paid subscription for use in larger companies. Podman is a free alternative; with it, set KIND_EXPERIMENTAL_PROVIDER=podman.

OSCommands
macOS (Homebrew)
brew install kind kubectl helm
# plus Docker Desktop, or: brew install podman && podman machine init --cpus 4 --memory 8192 && podman machine start
Windows
# install WSL2 + Ubuntu, then Docker Desktop (WSL2 backend) or Podman Desktop
# inside Ubuntu, follow the Linux row
Linux
# Docker Engine or Podman from your distro, then the kind, kubectl and helm
# release binaries for the versions in lab/versions.env (install-tools.sh does this)
./lab/install-tools.sh
kind version
kubectl version --client
helm version --short

4. Start the lab

From the course repository, run:

./lab/lab-up.sh

The script:

  1. starts the registry container on 127.0.0.1:5001;
  2. creates the cluster from kind-config.yaml;
  3. connects the registry to the cluster's network and tells each node about it;
  4. installs metrics-server (with --kubelet-insecure-tls, which a local lab needs and production never should);
  5. waits until every node is Ready.

It takes 1–3 minutes the first time, while the node images download.

5. Check it works

List the nodes with their zone label as an extra column.

Show all nodes with a column for the topology.kubernetes.io/zone label.

kubectl get nodes -L topology.kubernetes.io/zone

Also accepted: --label-columns for -L, node/no for nodes, and an added -o wide.

-L adds one column per label key you name.
NAME               STATUS   ROLES           AGE   VERSION   ZONE
kq-control-plane   Ready    control-plane   2m    v1.3x.x
kq-worker          Ready    <none>          2m    v1.3x.x   zone-1
kq-worker2         Ready    <none>          2m    v1.3x.x   zone-2
kq-worker3         Ready    <none>          2m    v1.3x.x   zone-3
kq-worker4         Ready    <none>          2m    v1.3x.x   zone-1

In this lab, what does localhost:5001 stand in for?

  1. The AKS API server The API server is the control-plane node, reached through your kubeconfig.
  2. Azure Container Registry
  3. Azure Key Vault There's no local Key Vault; secret-store boxes use Kubernetes Secrets instead.
  4. An Azure DevOps agent Pipelines aren't run locally in this course.
You push images to localhost:5001/orders-api:tag and the cluster pulls them, just as AKS pulls from contosoacr.azurecr.io. The difference: no authentication is needed locally, whereas AKS needs the AcrPull role.

6. Stop, reset and the small variant

  • ./lab/lab-down.sh deletes the cluster and the registry. Your files are untouched.
  • Reset: run lab-down.sh, then lab-up.sh. Every box assumes a fresh lab plus the add-ons it names.
  • Small machine? ./lab/lab-up.sh --small creates a single node with the registry and metrics-server. Most boxes work. Chapter 3's zone and taint boxes say when they need the full lab.
  • Each box ends with its own cleanup commands, so you rarely need a full reset.
./lab/lab-down.sh
./lab/lab-up.sh --small

Tick "I'm set up" once kubectl get nodes shows every node Ready.

This unlocks the "I tried it" ticks on every "Try it locally" box (5 XP each, never graded).
