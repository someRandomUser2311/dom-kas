Shell & scripting basics

You'll be able to read and write the short Bash scripts that pipelines run, and make them fail loudly instead of silently.

1. Pipelines run shell scripts

Every script: step in Azure Pipelines and every AzureCLI@2 task runs a shell script on an agent. On Linux agents, that's Bash.

You don't need to be a Bash expert. You do need six things, and this lesson covers each:

  • variables
  • quoting
  • capturing output
  • exit codes
  • simple if/for
  • reading JSON
#!/usr/bin/env bash
set -euo pipefail

RG="rg-orders-dev"
CLUSTER="aks-orders-dev"

az aks get-credentials --resource-group "$RG" --name "$CLUSTER"
kubectl apply -f k8s/
Windows/IIS admin
Bash plays the role of PowerShell here. The big difference is that Bash passes text between commands, not objects. That's why we'll use --query and jq to pick values out of JSON.
Linux admin
Nothing new here. Skim this lesson and take the check at the end.
Developer (Compose)
It's the same shell you use for docker compose up. The new part is making scripts safe for unattended runs.
Other clouds
Same Bash you'd use with the aws or gcloud CLI. az just replaces them.

2. Variables and quoting

Set a variable with NAME=value, with no spaces around =. Read it with $NAME or ${NAME}.

Always wrap variables in double quotes when you use them: "$RG". Without quotes, a value containing a space is split into two arguments.

Single quotes stop expansion completely: '$RG' is literally the text $RG.

export NAME=value makes the variable visible to programs the script starts, such as terraform reading ARM_SUBSCRIPTION_ID.

RG="rg-orders-dev"          # no spaces around =
echo "Deploying to $RG"       # → Deploying to rg-orders-dev
echo 'Deploying to $RG'       # → Deploying to $RG
export ARM_SUBSCRIPTION_ID="00000000-0000-0000-0000-000000000000"

Azure Pipelines has its own variable syntax, $(name), which the pipeline replaces before Bash runs. Inside a script, $(name) and Bash's $(command) look alike. Chapter 7 covers how to tell them apart.

3. Capture a command's output with $(…)

$(command) runs the command and substitutes its output. That's how you pass the result of one command to the next.

With az, combine it with --query (a JMESPath expression that picks fields from the JSON result) and -o tsv (plain text without quotes). That gives you a clean value to store.

ACR_ID=$(az acr show --name contosoacr --query id -o tsv)
echo "$ACR_ID"
# /subscriptions/…/resourceGroups/rg-orders-dev/providers/Microsoft.ContainerRegistry/registries/contosoacr

Complete the line so KUBELET_ID holds just the object ID, with no quotes or JSON.

KUBELET_ID=$(az aks show -g rg-orders-dev -n aks-orders-dev \
  --query identityProfile.kubeletidentity.objectId ?)
  • -o tsv
  • -o json JSON output wraps the value in quotes, so the variable would contain "…".
  • -o table Table output adds a header row and a dashed line.
  • | jq That would pretty-print JSON, still with quotes. You'd need jq -r to get raw text.
-o tsv prints bare values: exactly what you want inside $(…).

4. Exit codes, and why set -euo pipefail matters

Every command returns an exit code: 0 means success, and anything else means failure. $? holds the last one.

By default, Bash keeps going after a failed command. In a pipeline that's dangerous: a failed login can be followed by a "successful" deploy step that deploys nothing, or the wrong thing.

Put this line at the top of every script:

  • -e: stop at the first failing command.
  • -u: treat an unset variable as an error, so a typo like $RGG can't silently become empty.
  • -o pipefail: a pipeline (a | b) fails if any part fails, not just the last.
#!/usr/bin/env bash
set -euo pipefail

This script runs without set -e. The cluster name is misspelled, so get-credentials fails. What happens?

az aks get-credentials -g rg-orders-dev -n aks-orders-dve
kubectl apply -f k8s/
echo "Deployed!"
  1. The script stops after the first line Only with set -e.
  2. kubectl apply still runs, against whatever cluster the kubeconfig already points at, and the script prints "Deployed!"
  3. Bash asks whether to continue Scripts never prompt like that.
Without -e, Bash ignores the failure. kubectl uses the current context, which on a reused self-hosted agent could be a different cluster. With set -e, the script stops at line 1 and the pipeline step fails.

5. if and for

if tests a command's exit code. [ … ] (or [[ … ]] in Bash) is itself a command that compares things.

for loops over a list of words.

ENVIRONMENT="prod"
if [[ "$ENVIRONMENT" == "prod" ]]; then
  echo "Production: two approvals needed"
fi

for ns in dev staging prod; do
  kubectl get pods -n "$ns"
done

if kubectl get namespace orders >/dev/null 2>&1; then
  echo "namespace exists"
fi

>/dev/null 2>&1 throws away both normal output and errors, so you only use the exit code. You'll see it often in "does this exist?" checks.

6. Reading JSON: --query and jq

Cloud CLIs return JSON. There are two ways to pick values out of it:

  • az … --query uses JMESPath and is built into the Azure CLI. [].name lists every item's name, and [?location=='westeurope'].name filters first.
  • jq works on any JSON, including kubectl … -o json. Use jq -r for raw text without quotes.
az group list --query "[?location=='westeurope'].name" -o tsv

kubectl get pods -n orders -o json \
  | jq -r '.items[] | select(.status.phase != "Running") | .metadata.name'

7. Long commands: line continuation

A backslash \ at the very end of a line continues the command on the next line. It must be the last character: a trailing space after it breaks the command.

You'll see this in every az aks create example.

az aks create \
  --resource-group rg-orders-dev \
  --name aks-orders-dev \
  --node-count 3 \
  --enable-oidc-issuer \
  --enable-workload-identity
Windows/IIS admin
PowerShell uses a backtick ` for the same thing. In PowerShell, $x = az … --query id -o tsv captures output, and $LASTEXITCODE holds a native command's exit code. Careful: $ErrorActionPreference = 'Stop' does not stop on failed native commands like az in older PowerShell versions. Check $LASTEXITCODE, or set $PSNativeCommandUseErrorActionPreference = $true on PowerShell 7.4+.
Linux admin
Same as always.
Developer (Compose)
Same as multi-line docker run commands.
Other clouds
Same as the AWS and GCP CLI docs.

Print only the ID of the resource group rg-orders-dev, as plain text.

az group show --name rg-orders-dev --query id -o tsv

Also accepted: -n for --name, --output tsv for -o tsv, flags in any order.

az group show returns the group as JSON. --query id picks one field, and -o tsv prints it bare.

Shell, sorted

  • NAME=value with no spaces; use it as "$NAME", always quoted.
  • $(command) captures output; with az, add --query … -o tsv.
  • Start every pipeline script with set -euo pipefail.
  • if tests exit codes; for loops over words.
  • Use --query for az output and jq -r for any JSON.
  • \ at the very end of a line continues the command.
