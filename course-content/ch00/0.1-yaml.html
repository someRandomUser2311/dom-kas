YAML in 10 minutes

You'll be able to read and write the YAML used by Kubernetes manifests and Azure Pipelines, and avoid the four mistakes that break most files.

1. Why YAML is everywhere in this course

Almost every file you'll touch in this course is YAML:

  • Kubernetes manifests
  • Azure Pipelines definitions
  • Helm values
  • Kustomize overlays

YAML is a way of writing data: names, numbers, lists and nested settings. It doesn't run anything.

A tool reads the file and turns it into a structure. Kubernetes turns it into an object, and Azure Pipelines turns it into a run plan. Learning YAML is really learning to see that structure.

# a comment starts with #
name: orders-api
replicas: 3
public: false
Windows/IIS admin
Think of it as a web.config or .ini file, without the angle brackets. Indentation replaces the closing tags.
Linux admin
It's like a config file in /etc, but with real nesting and lists. Netplan and Ansible use the same format.
Developer (Compose)
You already write YAML: docker-compose.yml is YAML. Everything here applies to it too.
Other clouds
CloudFormation and GitHub Actions use YAML. Same rules, different keys.

2. Maps: key, colon, space, value

The basic unit is a map: a set of key: value pairs. The space after the colon is required.

To nest a map inside a key, put nothing after the colon and indent the children underneath. Indent with spaces only, never tabs; two spaces per level is the convention.

Every line at the same indentation belongs to the same parent.

metadata:
  name: orders-api
  labels:
    app: orders
    tier: backend
A live YAML → tree view. The left pane is editable YAML; the right pane draws the parsed structure (maps as boxes, lists as numbered items, scalars with their type: string, number, boolean, null). Parse errors are flagged inline on the offending line. Starts with the file above.

Indentation amount doesn't matter to the parser, as long as siblings line up exactly. Two spaces is what kubectl, Helm and Azure DevOps all generate, so stick with it.

3. Spot the broken indentation

One extra or missing space moves a key to a different parent, or makes the file invalid.

metadata:
  name: orders-api
  labels:
    app: orders
     tier: backend

Tap the line that breaks this file.

tier is indented five spaces, but its sibling app uses four. Siblings must line up exactly, so the parser fails with "mapping values are not allowed here" or similar.

4. Lists, and lists of maps

A list (also called a sequence) is a set of items, each starting with - (a dash and a space).

The pattern you'll see everywhere is a list of maps. Each - name: … starts a new item, and the keys under it, indented to line up with name, belong to that item.

ports:
  - 80
  - 443
containers:
  - name: api
    image: contosoacr.azurecr.io/orders-api:1.4.2
  - name: log-shipper
    image: fluent/fluent-bit:3.1
Same tree view, now showing containers as a list with two items, each item a map with name and image.

Complete the file so that sidecar becomes a second container, not a key inside the first one.

containers:
  - name: api
    image: orders-api:1.4.2
  ? name: sidecar
    image: fluent-bit:3.1
  • -
  • * YAML lists use a dash, not an asterisk. * starts an alias.
  • + YAML has no + list marker.
  • : A colon separates a key from its value; it doesn't start an item.
The dash starts a new list item. Without it, name: sidecar would collide with the first item's name.

5. Strings, numbers and the quoting traps

YAML guesses each value's type. Most of the time that's what you want; sometimes it isn't.

  • replicas: 3 is a number.
  • version: 1.20 is the number 1.2. The trailing zero is lost.
  • enabled: yes, on and no become booleans in the YAML 1.1 rules that Kubernetes' YAML library still follows.
  • zip: 01234 may be read as a number and lose its leading zero.

When a value must stay text, quote it: "1.20", "yes", "01234".

Environment variable values in Kubernetes must be strings, so value: "8080" needs the quotes.

kubernetesVersion: "1.30"   # quoted: stays "1.30"
replicas: 3                 # number
featureFlag: "on"           # quoted: stays the text "on"
env:
  - name: PORT
    value: "8080"           # env values must be strings

What does version: 1.20 parse as?

  1. The string "1.20" Only if it's quoted. Unquoted, YAML reads it as a number.
  2. The number 1.2
  3. The number 1.20, kept exactly Numbers don't keep trailing zeros, so 1.20 and 1.2 are the same value.
  4. A parse error It's valid YAML. That's what makes the bug easy to miss.
Unquoted 1.20 is a floating-point number, which is stored as 1.2. This is how a Kubernetes version "1.20" silently becomes "1.2". Quote version strings.

6. Multi-line strings: | and >

Scripts and certificates often span several lines. YAML has two block styles:

  • | (literal) keeps line breaks. Use it for scripts, config files and certificates.
  • > (folded) joins lines with spaces. Use it for long prose that you want to wrap in the file.

The text block is indented under its key. You'll use | constantly in pipeline script: steps and ConfigMaps.

steps:
  - script: |
      echo "Building $(Build.BuildId)"
      docker build -t orders-api .
    displayName: Build image
description: >
  This text is folded
  into one line.

Add - after the indicator (|-) to drop the final newline, or + to keep all trailing newlines. You'll rarely need either.

7. Comments and several documents in one file

A # starts a comment that runs to the end of the line. Inside quotes it's just a character.

A line containing only --- separates documents. Kubernetes uses this to put several objects in one file, for example a Deployment and its Service. kubectl apply -f applies each document as a separate object.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: orders-api   # the Deployment
---
apiVersion: v1
kind: Service
metadata:
  name: orders-api   # the Service, a second document

Fix the file in the tree view until it parses.

Starts with a broken file: a tab used for indentation on line 3, a missing space after a colon (name:web) on line 4, and a list item missing its dash. The step completes when the file parses with no errors and the tree shows spec.containers as a list of two maps.
spec:
  containers:
	- name: api
    image:web
    name: sidecar
    image: fluent-bit:3.1
Solution 
spec:
  containers:
    - name: api
      image: web
    - name: sidecar
      image: fluent-bit:3.1
Tabs are never allowed for indentation. key:value without a space is read as one string, not a key and value. And every list item needs its own dash.

YAML, sorted

  • Maps are key: value, with a space after the colon. Nesting is done by indentation with spaces only.
  • Lists use - . The - name: pattern is a list of maps.
  • Quote anything that must stay text: versions, "yes"/"on", leading zeros, and env values.
  • Use | to keep line breaks (scripts) and > to fold them (prose).
  • --- separates documents; # starts a comment.
