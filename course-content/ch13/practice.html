Write lab A: the Contoso cluster in Bicep

Brief: Write main.bicep (and modules if you like) plus main.prod.bicepparam for the Contoso platform. Graded by iac-rules (Bicep) with the same requirement set as Chapter 12 lab A.

  • The environment parameter uses @allowed(['dev','prod']).
  • Overlay networking: networkPlugin: 'azure', networkPluginMode: 'overlay'.
  • OIDC issuer and workload identity enabled.
  • aadProfile.enableAzureRBAC: true.
  • disableLocalAccounts: true.
  • The system pool spans zones 1, 2, 3 with at least 2 nodes and the CriticalAddonsOnly taint.
  • AcrPull for identityProfile.kubeletidentity.objectId with a deterministic guid() name.
  • A federated credential with issuer = oidcIssuerProfile.issuerURL and the correct subject.
  • Secret parameters use @secure(), and no secret values appear in .bicepparam (use getSecret() if needed).
Reference solution

Assemble lessons 13.2 (params, network), 13.3 (cluster, pool), 13.4 (identities, role assignments via a module scoped to rg-orders-shared), and 13.5 (bicepparam).

Write lab B: translate Terraform to Bicep

Given:

resource "azurerm_kubernetes_cluster_node_pool" "batch" {
  name                  = "batch"
  kubernetes_cluster_id = azurerm_kubernetes_cluster.main.id
  mode                  = "User"
  vm_size               = "Standard_D4ds_v5"
  zones                 = ["1", "2", "3"]
  auto_scaling_enabled  = true
  min_count             = 0
  max_count             = 5
  priority              = "Spot"
  node_taints           = ["batch=true:NoSchedule"]
}

resource "azurerm_role_assignment" "kubelet_acr_pull" {
  scope                = azurerm_container_registry.main.id
  role_definition_name = "AcrPull"
  principal_id         = azurerm_kubernetes_cluster.main.kubelet_identity[0].object_id
  principal_type       = "ServicePrincipal"
}

Write the Bicep equivalent. Graded by matching rules (no critical rules; this is translation practice).

  • An agentPools child resource with parent pointing at the cluster.
  • mode, vmSize, availabilityZones, enableAutoScaling/minCount/maxCount, scaleSetPriority: 'Spot' and nodeTaints all match.
  • A role assignment with scope: acr, the AcrPull role definition ID via subscriptionResourceId, the kubelet object ID, and principalType.
  • The role assignment name uses guid() with stable inputs.

Write lab C: the Bicep infra pipeline

Brief: Write infra-pipeline.yml for infra/bicep. Graded by pipeline-rules.

  • A lint or build step (az bicep lint / build).
  • A what-if stage against the target resource group.
  • Deploy runs in a deployment job with an environment.
  • Deploy runs only after the approval (environment) and the what-if stage, on main.
  • Authentication uses a service connection (WIF); no client secrets in the YAML.
  • The deploy step uses az deployment group create, az stack group create or AzureResourceManagerTemplateDeployment@3.
Reference solution

Lesson 13.8, step 3.

Walkthrough: what-if → stack deploy → portal change blocked

  1. az deployment group what-if on prod: read the + ~ * output.
  2. az stack group create … --deny-settings-mode denyWriteAndDelete.
  3. In the portal, try to change the user pool's max count: "denied by deny assignment".
  4. Change it in main.prod.bicepparam instead; the PR's what-if shows it; merge; the pipeline applies it.
