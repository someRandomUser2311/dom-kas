Loops, conditions & types

You'll be able to create resources in loops, deploy them conditionally, validate structured parameters with user-defined types, and write .bicepparam files per environment.

1. Loops

A for expression creates one resource (or property item) per element of an array: [for pool in nodePools: { … }]. Add an index with [for (pool, i) in nodePools: …].

param nodePools nodePool[]

resource pools 'Microsoft.ContainerService/managedClusters/agentPools@2024-09-01' = [for pool in nodePools: {
  parent: aks
  name: pool.name
  properties: {
    mode: 'User'
    vmSize: pool.vmSize
    availabilityZones: [ '1', '2', '3' ]
    enableAutoScaling: true
    minCount: pool.minCount
    maxCount: pool.maxCount
    scaleSetPriority: (pool.?spot ?? false) ? 'Spot' : 'Regular'
  }
}]
Terraform
for_each ↔ for … in. Each Bicep item is identified by its name property in Azure, not by array position. Removing the middle item doesn't shift the others the way Terraform's count does. But in incremental mode the removed pool isn't deleted either (lesson 13.7).

2. Fill the loop

Create one federated credential per namespace in the list.

param namespaces array = [ 'orders', 'orders-canary' ]

@batchSize(1)
resource feds 'Microsoft.ManagedIdentity/userAssignedIdentities/federatedIdentityCredentials@2023-01-31' = [?: {
  parent: ordersApiId
  name: 'fc-${ns}'
  properties: {
    issuer: aks.properties.oidcIssuerProfile.issuerURL
    subject: 'system:serviceaccount:${ns}:orders-api'
    audiences: [ 'api://AzureADTokenExchange' ]
  }
}]
  • for ns in namespaces
  • foreach ns in namespaces Bicep's keyword is for.
  • for_each = namespaces That's Terraform.
  • copy: namespaces That's the raw ARM JSON form.
@batchSize(1) deploys them one after another, which is required for federated credentials on the same identity (lesson 13.4).

3. Conditions

if (condition) before the body deploys a resource only when the condition is true.

resource gpuPool 'Microsoft.ContainerService/managedClusters/agentPools@2024-09-01' = if (isProd) {
  parent: aks
  name: 'gpu'
  properties: {
    mode: 'User'
    vmSize: 'Standard_NC4as_T4_v3'
    enableAutoScaling: true
    minCount: 0
    maxCount: 2
    nodeTaints: [ 'gpu=true:NoSchedule' ]
  }
}
Terraform
count = local.is_prod ? 1 : 0 ↔ if (isProd). No [0] indexing afterwards. Use the safe-access operator (gpuPool.?properties) when reading properties of a conditional resource.

4. Add the GPU pool in prod

Add a GPU node pool that's deployed only when environment is prod, tainted so ordinary pods stay off it.

Bicep editor. Graded by iac-rules (Bicep): with environment=prod the compiled template contains an agentPool with a GPU VM size and the gpu=true:NoSchedule taint; with dev it doesn't. Accepts if (isProd) or if (environment == 'prod').
A conditional resource plus a taint. Pods that need the GPU add a toleration and node affinity (lesson 3.2).

5. Ternaries

tier: isProd ? 'Standard' : 'Free'
minCount: isProd ? 3 : 1
apiServerAccessProfile: isProd ? { enablePrivateCluster: true } : { authorizedIPRanges: authorizedIpRanges }

6. User-defined types

Instead of param nodePools array, which accepts anything, define a type. Wrong shapes and typos then fail at build time, and editors autocomplete the fields.

@export()
type nodePool = {
  @minLength(1)
  @maxLength(12)
  name: string
  vmSize: string
  @minValue(0)
  minCount: int
  @maxValue(50)
  maxCount: int
  spot: bool?
}
import { nodePool } from 'types.bicep'
param nodePools nodePool[]
Terraform
Like type = list(object({ … optional(bool) })). The ? marks an optional property.

7. .bicepparam files

A parameters file in Bicep syntax, tied to one template with using. It's type-checked against the template.

using './main.bicep'

param environment = 'prod'
param userPoolMaxCount = 10
param nodePools = [
  { name: 'general', vmSize: 'Standard_D4ds_v5', minCount: 3, maxCount: 10 }
  { name: 'memory', vmSize: 'Standard_E8ds_v5', minCount: 0, maxCount: 4 }
]
param aksAdminGroupId = '00000000-0000-0000-0000-000000000000'

8. Secrets in parameter files: don't

If a template truly needs a secret parameter (@secure()), pull it from Key Vault at deploy time instead of writing it in the file:

  • getSecret() in the .bicepparam file;
  • or readEnvironmentVariable(), fed by the pipeline from a secret variable.
param sqlAdminPassword = getSecret('<subId>', 'rg-orders-shared', 'kv-contoso-shared', 'sql-admin-password')

9. Predict the resources

With main.dev.bicepparam (environment dev, nodePools = one general pool) and the template from steps 1–3, which agent pools exist after the first deployment?

  1. system, general, gpu The GPU pool is if (isProd).
  2. system (inside the cluster resource) and general
  3. general only The system pool is part of the cluster's agentPoolProfiles.
  4. system, general, memory memory is only in the prod parameters.
Conditions and loops are evaluated per deployment from the parameters. Use what-if to confirm.

10. Build the parameters

az bicep build-params --file main.prod.bicepparam      # → main.prod.parameters.json, type-checked
az deployment group what-if -g rg-orders-prod -f main.bicep -p main.prod.bicepparam

Loops & types, sorted

  • [for x in list: {…}] for resources and properties; @batchSize to serialise.
  • = if (cond) {…} for optional resources; ternaries for values.
  • User-defined types (type, @export/import) validate structured parameters.
  • .bicepparam with using; secrets via getSecret(), never literals.
