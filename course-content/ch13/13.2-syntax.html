Bicep syntax

You'll be able to write parameters with decorators, variables, resources with symbolic references, existing and child resources, and outputs, and grow main.bicep to a network and registry.

1. Parameters

A param declares an input, with a type and an optional default. Decorators (@…) add rules and documentation.

@description('Environment name.')
@allowed([ 'dev', 'prod' ])
param environment string

param location string = resourceGroup().location

@minValue(1)
@maxValue(20)
param userPoolMaxCount int = 5
Terraform
param ≈ variable. @allowed ≈ a validation with contains(). @secure() ≈ sensitive = true, but stronger: secure values are never stored in deployment history.

2. Complete the decorator

Restrict environment to dev or prod.

?
param environment string
  • @allowed([ 'dev', 'prod' ])
  • @validate('dev|prod') There's no @validate decorator.
  • @enum(dev, prod) Not Bicep syntax.
  • @secure() That hides values; it doesn't restrict them.
A deployment with environment = 'Prod' fails validation before anything is created. Bicep strings use single quotes.

3. Variables

+var nameSuffix = 'orders-${environment}'
+var isProd = environment == 'prod'
+var tags = {
+  app: 'orders'
+  environment: environment
+  managedBy: 'bicep'
+}

var ≈ Terraform locals. Interpolation uses '${…}' inside single-quoted strings.

4. A resource and its symbolic name

resource <symbolicName> '<type>@<apiVersion>' = { … }. The symbolic name is used to refer to the resource elsewhere in the file. It's like Terraform's local name, and Azure never sees it.

+resource vnet 'Microsoft.Network/virtualNetworks@2024-05-01' = {
+  name: 'vnet-${nameSuffix}'
+  location: location
+  tags: tags
+  properties: {
+    addressSpace: { addressPrefixes: [ '10.20.0.0/16' ] }
+    subnets: [
+      { name: 'snet-aks-nodes', properties: { addressPrefix: '10.20.0.0/22' } }
+      { name: 'snet-private-links', properties: { addressPrefix: '10.20.5.0/27' } }
+    ]
+  }
+}

5. Symbolic references and implicit dependencies

Use the symbolic name to read properties: vnet.id, vnet.name, vnet.properties.subnets[0].id.

Bicep generates dependsOn from these references automatically, so explicit dependsOn is rarely needed. The same rule as Terraform.

var aksSubnetId = vnet.properties.subnets[0].id

6. Child resources with parent

Some resources live under another: subnets under a VNet, agent pools under a cluster, federated credentials under an identity. Declare them with parent, and give just their own short name.

resource aksSubnet 'Microsoft.Network/virtualNetworks/subnets@2024-05-01' = {
  parent: vnet
  name: 'snet-aks-nodes'
  properties: { addressPrefix: '10.20.0.0/22' }
}

Declare subnets either inline in the VNet or as child resources, not both. Mixing them makes each deployment remove the other's subnets.

7. Existing resources

existing refers to a resource that's already there, without deploying it. It's like a Terraform data source. Add scope: when it's in another resource group.

Tap the declaration that refers to the shared registry without creating or changing it.

resource law 'Microsoft.OperationalInsights/workspaces@2023-09-01' = {
  name: 'log-${nameSuffix}'
  location: location
  properties: { sku: { name: 'PerGB2018' }, retentionInDays: 30 }
}

resource acr 'Microsoft.ContainerRegistry/registries@2023-07-01' existing = {
  name: 'contosoacr'
  scope: resourceGroup('rg-orders-shared')
}
The existing keyword. You can read acr.id and acr.properties.loginServer, and use it as a role-assignment scope. Nothing about it is deployed.

8. Useful functions

FunctionUse
resourceGroup().location, .idProperties of the target resource group
subscription().subscriptionId, tenant().tenantIdContext values
uniqueString(resourceGroup().id)A stable 13-character hash, for globally unique names
guid(a, b, c)A deterministic GUID from inputs (role assignment names, lesson 13.4)
subscriptionResourceId(...)The ID of a subscription-level resource such as a role definition

9. Globally unique names

A team wants a per-environment registry. Why name it 'acr${uniqueString(resourceGroup().id)}'?

  1. It's random on every deployment The opposite: it's deterministic, the same input gives the same output every time.
  2. Registry names are global; the hash is stable for this resource group but unique across Azure, so redeploys hit the same registry
  3. ACR requires hashes It requires globally unique alphanumeric names; a hash is one way to get one.
  4. To hide the name It's visible everywhere.
Never use newGuid() or utcNow() in names; they change every deployment (lesson 13.4).

10. Outputs

+output vnetId string = vnet.id
+output aksSubnetId string = vnet.properties.subnets[0].id
+output acrLoginServer string = acr.properties.loginServer

Outputs are recorded in deployment history and readable with az deployment group show --query properties.outputs. Never output secrets.

11. Secure parameters

@secure() on a string or object parameter keeps its value out of logs and deployment history. Better still, avoid secret parameters: use managed identities, or reference Key Vault from the parameters file with getSecret() (lesson 13.5).

@secure()
param sqlAdminPassword string

12. Lint and build

$ az bicep lint --file main.bicep
main.bicep(14,7) : Warning no-unused-params: Parameter "userPoolMaxCount" is declared but never used.
main.bicep(31,12) : Warning use-resource-symbol-reference: Use a resource reference instead of resourceId().

Rules are configured in bicepconfig.json. Raise important ones to error so the PR pipeline fails on them.

Syntax, sorted

  • param + decorators (@allowed, @minValue, @secure, @description); var; output.
  • resource sym 'type@api' = { … }; symbolic references create dependencies.
  • parent for children; existing (+ scope) for resources you don't deploy.
  • uniqueString and guid for stable names; lint everything.
