Building AKS in Bicep

You'll be able to write Contoso's cluster as a Microsoft.ContainerService/managedClusters resource, property by property, and map each one to its Terraform argument and CLI flag.

1. The skeleton

resource aks 'Microsoft.ContainerService/managedClusters@2024-09-01' = {
  name: 'aks-${nameSuffix}'
  location: location
  tags: tags
  sku: {
    name: 'Base'
    tier: isProd ? 'Standard' : 'Free'
  }
  properties: {
    dnsPrefix: 'aks-${nameSuffix}'
    nodeResourceGroup: 'rg-${nameSuffix}-nodes'
  }
}
Terraform
One resource, like azurerm_kubernetes_cluster, but property names follow the ARM API (camelCase, nested under properties) instead of the provider's snake_case. A side-by-side table is at step 13.

2. The cluster's identity

+  identity: {
+    type: 'UserAssigned'
+    userAssignedIdentities: {
+      '${aksIdentity.id}': {}
+    }
+  }

The odd-looking map, keyed by the identity's resource ID with an empty object, is simply how ARM represents user-assigned identities.

4. Networking

Complete the overlay setting.

    networkProfile: {
      networkPlugin: 'azure'
      ?: 'overlay'
      networkDataplane: 'cilium'
      networkPolicy: 'cilium'
      podCidr: '192.168.0.0/16'
      serviceCidr: '172.16.0.0/16'
      dnsServiceIP: '172.16.0.10'
      outboundType: 'loadBalancer'
    }
  • networkPluginMode
  • network_plugin_mode That's the Terraform spelling; ARM properties are camelCase.
  • networkMode A different, legacy property.
  • overlayMode Not a property.
Same setting, three spellings: --network-plugin-mode (CLI), network_plugin_mode (Terraform), networkPluginMode (Bicep/ARM).

5. OIDC and workload identity

+    oidcIssuerProfile: { enabled: true }
+    securityProfile: {
+      workloadIdentity: { enabled: true }

6. Entra ID, Azure RBAC, no local accounts

+    aadProfile: {
+      managed: true
+      enableAzureRBAC: true
+      adminGroupObjectIDs: [ aksAdminGroupId ]
+    }
+    disableLocalAccounts: true

Tap the property that removes the static admin credential.

disableLocalAccounts: true, which is local_account_disabled in Terraform and --disable-local-accounts on the CLI.

7. API server access

+    apiServerAccessProfile: isProd ? {
+      enablePrivateCluster: true
+      privateDNSZone: privateDnsZoneId
+    } : {
+      enablePrivateCluster: false
+      authorizedIPRanges: authorizedIpRanges
+    }

A ternary between two objects gives one clear shape per environment. In Terraform this needed a dynamic block.

8. Upgrades

Maintenance windows are a separate child resource, Microsoft.ContainerService/managedClusters/maintenanceConfigurations, named aksManagedNodeOSUpgradeSchedule (lesson 4.4).

10. The user pool: a child resource

resource userPool 'Microsoft.ContainerService/managedClusters/agentPools@2024-09-01' = {
  parent: aks
  name: 'user'
  properties: {
    mode: 'User'
    vmSize: 'Standard_D4ds_v5'
    availabilityZones: [ '1', '2', '3' ]
    vnetSubnetID: aksSubnetId
    osSKU: 'AzureLinux'
    enableAutoScaling: true
    minCount: isProd ? 3 : 1
    maxCount: userPoolMaxCount
    count: isProd ? 3 : 1
  }
}

Like Terraform's ignore_changes on node counts, be careful re-deploying count on an autoscaled pool. The autoscaler adjusts it within min and max, and a deployment can reset it. Many teams omit count on updates, or set it equal to minCount.

11. Private in prod, via a parameter

The cluster currently has enablePrivateCluster: false hard-coded. Make it private only when environment is prod.

A Bicep editor. Graded by iac-rules (Bicep) with environment=dev and =prod: prod compiles to enablePrivateCluster: true (no authorized IP ranges); dev compiles to false with the ranges. Using isProd or comparing environment directly both pass.
Derive environment switches from the one environment parameter, as step 7 does.
