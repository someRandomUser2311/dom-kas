Chapter 12 · Infrastructure as code with Terraform

Everything Contoso built by hand in Chapters 4–6 (the network, registry, cluster and identities) becomes code in infra/terraform/, reviewed in pull requests and applied by a pipeline. Chapter 13 builds the same platform in Bicep, so you can compare the two line for line.

By the end, you can

  • Explain why infrastructure should be code, and what belongs in IaC vs the app pipeline.
  • Write HCL fluently: providers, resources, variables (with validation), locals, outputs, data sources, count/for_each, dynamic blocks.
  • Build the Contoso platform with azurerm: resource group, VNet and subnets, ACR, AKS (+ user pool), Log Analytics, AcrPull for the kubelet identity, and a workload identity with a federated credential.
  • Structure code with modules (your own and Azure Verified Modules), and pin provider and module versions.
  • Manage state safely: azurerm remote backend, locking, sensitive values, import/moved blocks, drift.
  • Run Terraform in Azure Pipelines: PR checks, a saved plan → approval → apply, OIDC authentication.
