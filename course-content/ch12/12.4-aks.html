Building AKS

You'll be able to write Contoso's AKS cluster in Terraform, one decision at a time. Every block maps to a choice you made with the CLI in Chapters 4–6.

1. The skeleton

Start with the required arguments. dns_prefix becomes part of the API server's hostname.

resource "azurerm_kubernetes_cluster" "main" {
  name                = "aks-${local.name_suffix}"
  location            = azurerm_resource_group.main.location
  resource_group_name = azurerm_resource_group.main.name
  dns_prefix          = "aks-${local.name_suffix}"
  node_resource_group = "rg-${local.name_suffix}-nodes"
  sku_tier            = local.is_prod ? "Standard" : "Free"
  tags                = local.tags
}
Portal/ARM
Each block maps to a section of the portal's "Create Kubernetes cluster" wizard, or to properties of Microsoft.ContainerService/managedClusters.
az CLI scripts
Each block replaces a group of az aks create flags from lesson 4.6, listed side by side in step 14.
CloudFormation
Like an AWS::EKS::Cluster plus nodegroups, with a lot more in one resource.
Pulumi
The same properties as azure-native.containerservice.ManagedCluster.

2. The system node pool

Every cluster needs a default_node_pool, which is our system pool (lesson 4.2): three zones, critical add-ons only, in Contoso's subnet. temporary_name_for_rotation lets Terraform change settings that need the pool recreated.

+  default_node_pool {
+    name                         = "system"
+    vm_size                      = "Standard_D4ds_v5"
+    node_count                   = 3
+    zones                        = ["1", "2", "3"]
+    only_critical_addons_enabled = true
+    vnet_subnet_id               = azurerm_subnet.aks_nodes.id
+    os_sku                       = "AzureLinux"
+    temporary_name_for_rotation  = "systemtmp"
+    upgrade_settings {
+      max_surge = "33%"
+    }
+  }

only_critical_addons_enabled = true adds the CriticalAddonsOnly=true:NoSchedule taint from lesson 4.2.

3. The cluster's identity

+  identity {
+    type         = "UserAssigned"
+    identity_ids = [azurerm_user_assigned_identity.aks.id]
+  }

A user-assigned identity, created in identity.tf (lesson 12.5), so we can grant it Network Contributor on the subnet before the cluster exists.

4. Networking

+  network_profile {
+    network_plugin      = "azure"
+    network_plugin_mode = "overlay"
+    network_data_plane  = "cilium"
+    network_policy      = "cilium"
+    pod_cidr            = "192.168.0.0/16"
+    service_cidr        = "172.16.0.0/16"
+    dns_service_ip      = "172.16.0.10"
+    outbound_type       = "loadBalancer"
+  }

Which argument makes pods use the overlay range instead of VNet IPs?

  network_profile {
    network_plugin      = "azure"
    ? = "overlay"
  • network_plugin_mode
  • network_mode A different, older setting (bridge/transparent).
  • network_data_plane That picks Cilium vs Azure, not overlay.
  • pod_cidr The range, not the mode.
The same as --network-plugin-mode overlay in lesson 4.6.

6. Entra ID + Azure RBAC, no local accounts

Tap the argument that removes the static admin kubeconfig.

local_account_disabled = true. The admin group keeps an Entra ID way in, so you can't lock yourself out.

7. Public in dev, private in prod

Authorized IP ranges only apply to public clusters (lesson 6.4), so the block is generated only in dev. Lesson 12.6 explains dynamic blocks.

10. The user node pool

Extra pools are separate resources. They can then be added or removed without touching the cluster resource.

resource "azurerm_kubernetes_cluster_node_pool" "user" {
  name                  = "user"
  kubernetes_cluster_id = azurerm_kubernetes_cluster.main.id
  mode                  = "User"
  vm_size               = var.user_pool.vm_size
  zones                 = ["1", "2", "3"]
  vnet_subnet_id        = azurerm_subnet.aks_nodes.id
  os_sku                = "AzureLinux"
  auto_scaling_enabled  = true
  min_count             = var.user_pool.min_count
  max_count             = var.user_pool.max_count
  tags                  = local.tags
}

11. The container registry

Contoso's registry is shared by dev and prod, so it lives in a small separate configuration (infra/terraform/shared). The cluster configurations read it with a data source.

resource "azurerm_container_registry" "main" {
  name                          = "contosoacr"
  resource_group_name           = azurerm_resource_group.shared.name
  location                      = azurerm_resource_group.shared.location
  sku                           = "Premium"
  admin_enabled                 = false
  public_network_access_enabled = false
}
data "azurerm_container_registry" "shared" {
  name                = "contosoacr"
  resource_group_name = "rg-orders-shared"
}

12. Dev vs prod with one variable

In the editor, make prod use the Standard tier and a private cluster, while dev stays Free and public, driven only by var.environment.

The cluster from steps 1–9, with sku_tier and private_cluster_enabled hard-coded. Graded by iac-rules with environment=dev and environment=prod: prod plans sku_tier = "Standard" and private_cluster_enabled = true; dev plans Free and false; no other differences.
Use local.is_prod (lesson 12.3) in both arguments, which is exactly how steps 1 and 7 do it.

Building AKS, sorted

  • azurerm_kubernetes_cluster with a system default_node_pool, user-assigned identity, overlay + Cilium, OIDC + workload identity, Azure RBAC, no local accounts.
  • Private in prod, authorized IPs in dev, from one variable.
  • Upgrade channels and a maintenance window; oms_agent to Log Analytics.
  • User pools as separate azurerm_kubernetes_cluster_node_pool resources; the shared ACR read through a data source.
