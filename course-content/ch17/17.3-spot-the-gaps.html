Spot the gaps

You'll be able to review a colleague's first-draft repository the way the readiness review will, and find the planted problems across files.

1. The first draft

A colleague assembled a first draft of the repo. It deploys, but it has about 10 problems. Some are obvious, some subtle, and some only visible when you compare two files. Find them, file by file.

A file tree with tabs for each file. Every line is tappable. Tapping a planted problem marks it found (✓) with an explanation; tapping a fine line says "looks fine". A counter shows "found 0 / 10".

2. Dockerfile

Tap the problem in the Dockerfile.

FROM golang:latest AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -o /out/orders-api ./cmd/orders-api
FROM gcr.io/distroless/static-debian12:nonroot@sha256:…
COPY --from=build /out/orders-api /orders-api
USER nonroot:nonroot
ENTRYPOINT ["/orders-api"]
An unpinned :latest build image means non-reproducible builds (lessons 1.1, 16.2).

3. Deployment

Tap the most dangerous line.

image: contosoacr.azurecr.io/orders-api:1.6.0
resources:
  requests: { cpu: 250m, memory: 256Mi }
  limits:   { memory: 512Mi }
readinessProbe:
  httpGet: { path: /readyz, port: http }
livenessProbe:
  httpGet: { path: /health/db, port: http }
securityContext:
  allowPrivilegeEscalation: false
  readOnlyRootFilesystem: true
  capabilities: { drop: ["ALL"] }
Liveness depends on the database, the death spiral (lessons 3.3, 14.3).

4. Service vs Deployment

Compare the two files. What's wrong?

selector:
  app: orders-api
  tier: api
ports:
  - port: 80
    targetPort: http
labels:
  app: orders-api
  azure.workload.identity/use: "true"
  1. The Service selects tier: api, which the pods don't have, so it has no endpoints
  2. targetPort as a name is invalid Named ports are valid.
  3. The workload identity label breaks Services Extra labels don't matter.
A cross-file problem, found by cross-ref (lessons 2.2, 2.4).

5. Policies

Tap the line that defeats default-deny.

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: temp-debug
  namespace: orders
spec:
  podSelector: {}
  policyTypes: [Ingress]
  ingress:
  - {}
An allow-all rule left over from debugging. Policies are additive, so it opens everything (lesson 9.2).

6. Secrets

Tap the secret in Git.

configMapGenerator:
  - name: orders-api-config
    literals:
      - LOG_LEVEL=warn
      - PAYMENTS_API_KEY=pk_live_51Hx…
      - FEATURE_EXPRESS_SHIPPING=true
A live API key in a ConfigMap in Git. Move it to Key Vault, delivered by the SecretProviderClass (lesson 15.4), and rotate the key now.

7. Infrastructure

Select the problems in this Terraform excerpt.

resource "azurerm_kubernetes_cluster" "main" {
  sku_tier                  = "Free"
  private_cluster_enabled   = true
  oidc_issuer_enabled       = true
  workload_identity_enabled = true
  local_account_disabled    = false
  default_node_pool {
    name       = "system"
    vm_size    = "Standard_D4ds_v5"
    node_count = 1
    zones      = ["1", "2", "3"]
  }
}
  1. The Free tier for prod (no SLA)
  2. local_account_disabled = false
  3. node_count = 1, so a single system node can't actually span three zones
  4. private_cluster_enabled = true Required by the brief.
  5. oidc_issuer_enabled = true Required for workload identity.
Lessons 4.2, 4.5, 5.5 and 12.4.

8. Pipelines

Select the problems in the release pipeline excerpt.

- stage: DeployProd
  dependsOn: Build
  jobs:
    - job: deploy
      pool: { vmImage: ubuntu-latest }
      steps:
        - task: KubernetesManifest@1
          inputs:
            action: deploy
            kubernetesServiceConnection: aks-prod-admin
            manifests: $(Pipeline.Workspace)/manifests/*.yaml
            containers: contosoacr.azurecr.io/orders-api:$(Build.BuildId)
  1. A plain job, not a deployment job with the prod environment, so there's no approval or canary
  2. A Microsoft-hosted agent can't reach the private cluster
  3. A Kubernetes service connection with admin credentials, instead of WIF with a namespace-scoped role
  4. Deploys by tag rather than the signed digest; no DeployDev stage in between
  5. action: deploy That's the correct action.
Chapters 6, 7, 10, 11, 15 and 16, all in one stage.

9. What the review looks like
