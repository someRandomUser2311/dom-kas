The brief

You'll be able to read Contoso's production requirements, trace each one to the chapter that taught it, and to the file in the repo that satisfies it.

1. The memo

From: Contoso CTO. To: the platform team.

"Orders goes to production next quarter. Before launch, I need these requirements met, and verified automatically, not by someone's word."

  1. Private cluster: no public management endpoint for prod.
  2. Two environments: dev and prod, from the same code.
  3. Canary releases to prod, with automatic rollback.
  4. Zero secrets in Git, and no secrets in pods where avoidable.
  5. Default-deny networking: only the flows the app needs.
  6. Signed images only, from our registry.
  7. SLO alerting: we hear about problems before customers do.

2. Requirements → chapters

Requirement 4, "zero secrets in Git", is met by techniques from which chapters? Select all.

  1. Chapter 5: workload identity

  3. Chapter 15: Key Vault via the Secrets Store CSI driver

Most requirements draw on several chapters. That's why the capstone grades every file together.

6. Non-goals

Out of scope for launch:

  • multi-region;
  • a service mesh;
  • GitOps controllers;
  • running the database on AKS (it stays Azure Database for PostgreSQL).

Knowing what not to build is part of the brief.

7. Choose your IaC language

You'll submit infra/terraform/ or infra/bicep/. Both are graded against the same requirement rules, so the score is identical. Submit both for the "Bilingual IaC" badge.
