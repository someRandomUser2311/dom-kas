2. Why a hub?

Why put Azure Firewall and the DNS resolver in a hub, instead of in the AKS VNet?

  1. AKS forbids firewalls in its VNet It doesn't.
  2. They're shared by every spoke (other apps, agents, on-premises), managed centrally, and egress and DNS stay consistent
  3. It's cheaper per cluster to have one each The opposite: sharing is the saving.
  4. Private clusters require it They need DNS resolution, not a specific topology.
Lessons 5.3 and 6.5.

3. Why private AKS with Managed DevOps Pools?

Why does the prod deploy run on a Managed DevOps Pool in a peered VNet?

  1. It's faster than hosted agents Speed isn't the reason.
  2. The API server is private; agents need a network route and private DNS to reach it, without anyone patching agent VMs
  3. Hosted agents can't run kubectl They can, just not against a private endpoint.
  4. Licensing Unrelated.
Lessons 6.5–6.6.

4. Why Application Gateway for Containers?

Why AGC rather than the app routing add-on for prod?

  1. A WAF requirement, plus Gateway API weighted routing for canaries, with the data plane outside the cluster
  2. The add-on can't do TLS It can.
  3. AGC is free It's billed.
  4. It's required for private clusters Both work with private clusters.
Lesson 8.5.

5. Why private endpoints for ACR, Key Vault and the database?

With private endpoints in place, what else must be true for images to pull?

  1. Public access enabled The point is to disable it.
  2. privatelink.azurecr.io resolves from the AKS VNet (through the hub DNS), and the kubelet has AcrPull
  3. The admin user enabled Never.
  4. NodePort Services Unrelated.
Lessons 6.2–6.3.

6. Why workload identity everywhere?

How does orders-api reach PostgreSQL without a password?

  1. A password in a Secret That's what we're avoiding.
  2. Its workload identity is an Entra ID user on Azure Database for PostgreSQL; the app gets a token via DefaultAzureCredential
  3. The kubelet identity Never use the kubelet identity for apps.
  4. The pipeline's identity The pipeline doesn't run the app.
Lessons 5.6 and 15.4. Key Vault is kept for third-party API keys.

7. Zones and resilience

Node pools span zones 1–3, pods spread with topology constraints, and PDBs allow one disruption. The database is zone-redundant and AGC is zonal. One datacentre can fail without an outage (Chapters 3–4).

8. Observability

Container Insights, managed Prometheus, Grafana dashboards for the golden signals, kube-audit-admin logs, and an SLO burn alert on the 5xx ratio. The same metric gates the canary (Chapters 11 and 14).

9. What would you change?

Good reviews end with trade-offs. Cost: AGC + Premium ACR + Firewall add up for a small app. Complexity: a hub needs a network team. Alternatives: the app routing add-on with a separate WAF, or AKS Automatic. Write down what you'd change if the budget halved. It's part of the capstone reflection.

Architecture, sorted

  • Hub (firewall, DNS, Bastion) + prod spoke (private AKS, AGC, private endpoints) + agents VNet.
  • Identity everywhere: WIF for pipelines, workload identity for apps.
  • Zones, PDBs, observability and SLO alerts that also gate releases.
  • Every choice traced to a chapter, with its trade-offs stated.
