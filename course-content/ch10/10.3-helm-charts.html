Helm charts

You'll be able to read and write a small Helm chart, use the template functions that matter, and preview the rendered manifests before installing.

1. A chart is a folder

charts/orders-api/
├─ Chart.yaml            # name, chart version, appVersion
├─ values.yaml           # default settings
├─ templates/
│  ├─ _helpers.tpl       # reusable snippets (names, labels)
│  ├─ deployment.yaml
│  ├─ service.yaml
│  ├─ hpa.yaml
│  └─ NOTES.txt          # printed after install
└─ .helmignore

Helm renders the files in templates/ with the values, then sends the resulting YAML to the cluster.

Windows/IIS admin
A chart is like an MSI with a properties file: one package, configurable at install, upgradable and uninstallable.
Linux admin
Think apt/rpm packages with Jinja-like templates (Go templates here) and a values file.
Developer (Compose)
Like a Compose file with ${VARIABLES}, but much more powerful, and with install history.
Other clouds
Helm is the same everywhere. Many vendors ship their Kubernetes software as Helm charts.

2. Chart.yaml

apiVersion: v2
name: orders-api
description: Contoso Orders API
type: application
version: 0.3.0        # the chart's own version
appVersion: "1.4.2"   # the app version it deploys by default

3. values.yaml

replicaCount: 2

image:
  repository: contosoacr.azurecr.io/orders-api
  tag: ""             # empty = use the chart's appVersion

resources:
  requests: { cpu: 250m, memory: 256Mi }
  limits:   { memory: 512Mi }

autoscaling:
  enabled: true
  minReplicas: 2
  maxReplicas: 10

logLevel: info

4. A template

Inside {{ }}, .Values is the merged values, .Chart is Chart.yaml, and .Release is the install's name and namespace.

A - inside the braces ({{-) trims whitespace.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "orders-api.fullname" . }}
  labels:
    {{- include "orders-api.labels" . | nindent 4 }}
spec:
  {{- if not .Values.autoscaling.enabled }}
  replicas: {{ .Values.replicaCount }}
  {{- end }}
  selector:
    matchLabels:
      {{- include "orders-api.selectorLabels" . | nindent 6 }}
  template:
    metadata:
      labels:
        {{- include "orders-api.selectorLabels" . | nindent 8 }}
    spec:
      containers:
        - name: api
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
          env:
            - name: LOG_LEVEL
              value: {{ .Values.logLevel | quote }}
          resources:
            {{- toYaml .Values.resources | nindent 12 }}

5. Find the replicas

Tap the line that sets the number of replicas, and notice when it's skipped.

replicas: {{ .Values.replicaCount }}, but only when autoscaling is off. With the HPA on, the chart leaves replicas out so the HPA owns it (lesson 3.5).

7. Write an expression

The ConfigMap must hold the feature flag as the string "true" or "false". Complete the expression.

data:
  FEATURE_EXPRESS_SHIPPING: {{ .Values.features.expressShipping | ? }}
  • quote
  • toYaml This would output an unquoted true, a boolean that ConfigMap data rejects.
  • default default needs an argument and doesn't quote.
  • nindent 2 Indentation doesn't change the type.
ConfigMap values must be strings. quote wraps the rendered value in double quotes.

8. Helpers

_helpers.tpl defines named snippets with define, used with include. Every resource then gets identical names and labels, and the selector labels stay stable across upgrades.

{{- define "orders-api.fullname" -}}
{{ .Release.Name }}
{{- end }}

{{- define "orders-api.selectorLabels" -}}
app.kubernetes.io/name: {{ .Chart.Name }}
app.kubernetes.io/instance: {{ .Release.Name }}
{{- end }}

{{- define "orders-api.labels" -}}
{{ include "orders-api.selectorLabels" . }}
app.kubernetes.io/version: {{ .Values.image.tag | default .Chart.AppVersion | quote }}
app.kubernetes.io/managed-by: {{ .Release.Service }}
{{- end }}

9. Render without installing

helm template renders locally and prints the YAML, with no cluster needed. helm lint checks the chart. Use both in CI.

helm lint charts/orders-api
helm template orders-api charts/orders-api -f values-prod.yaml --set image.tag=1.4.2 | less
The chart's templates and values.yaml on the left (values editable), rendered manifests on the right. Changing autoscaling.enabled, replicaCount or image.tag re-renders live; errors from required show inline.

10. Predict the render

With the default values.yaml, plus --set image.tag="" and --set autoscaling.enabled=false, what do the image and replicas render as?

  1. image: "contosoacr.azurecr.io/orders-api:1.4.2" and replicas: 2
  2. image: "contosoacr.azurecr.io/orders-api:" and no replicas default treats an empty string as empty, so it falls back to appVersion; with autoscaling off, replicas is rendered.
  3. image: …:latest and replicas: 2 Nothing adds latest.
  4. A render error Both values are valid.
default replaces empty values ("", 0, false, null). That's handy here, and a trap when 0 or false is a real value you want.

11. Values per environment

autoscaling:
  minReplicas: 4
  maxReplicas: 20
resources:
  requests: { cpu: 500m, memory: 512Mi }
  limits:   { memory: 1Gi }
logLevel: warn

Later -f files and --set override earlier ones. Maps are merged; lists are replaced whole.

12. Schema validation

Add values.schema.json and Helm validates values against it on every lint, template and install. A typo like replicaCont or a wrong type fails immediately instead of silently being ignored.

Helm charts, sorted

  • Chart.yaml (version, appVersion), values.yaml, and templates/ with _helpers.tpl.
  • .Values, .Chart, .Release; default, quote, toYaml | nindent, if/range, required.
  • helm lint and helm template before installing.
  • Values files per environment; add a schema.
