Write lab A: RBAC for the deploy service account

Brief: Write k8s/rbac/deployer.yaml so ServiceAccount ci/deployer can deploy orders: Deployments, Services, ConfigMaps, HPAs and HTTPRoutes (get/list/watch/create/update/patch). Graded by rbac-eval against these cases:

ActionExpected
patch deployments -n ordersallow
create httproutes.gateway.networking.k8s.io -n ordersallow
update horizontalpodautoscalers.autoscaling -n ordersallow
get secrets -n ordersdeny
create pods/exec -n ordersdeny
delete deployments -n ordersdeny
patch deployments -n paymentsdeny
create clusterrolebindingsdeny
  • Every allow and deny case matches.
  • No wildcard (*) in verbs, resources or apiGroups.
  • No ClusterRoleBinding for the deploy service account.
  • The subject is the ServiceAccount deployer in namespace ci.

Walkthrough: can-i audit → tighten → verify

  1. kubectl get clusterrolebindings -o wide | grep serviceaccount: find the CI SA bound to cluster-admin.
  2. kubectl auth can-i --list --as=system:serviceaccount:ci:deployer shows everything.
  3. Apply the namespace-scoped Role and RoleBinding; delete the ClusterRoleBinding.
  4. Re-run the pipeline: it succeeds. can-i get secrets: no.

Try it locally

15.1 Roles and can-i.

kubectl create ns orders; kubectl create ns ci; kubectl create sa deployer -n ci
kubectl apply -f lab/examples/ch15/deployer-rbac.yaml
kubectl auth can-i patch deployments -n orders --as=system:serviceaccount:ci:deployer
kubectl auth can-i get secrets -n orders --as=system:serviceaccount:ci:deployer

Expected: yes, then no.

Cleanup: kubectl delete ns orders ci

15.3 Enforce restricted.

kubectl create ns psa-demo
kubectl label ns psa-demo pod-security.kubernetes.io/enforce=restricted
kubectl run bad -n psa-demo --image=busybox:1.36 --privileged -- sleep 3600
kubectl apply -n psa-demo -f lab/examples/ch15/hardened-pod.yaml

Expected: the first is rejected ("violates PodSecurity restricted…"); the hardened pod is created.

Cleanup: kubectl delete ns psa-demo
