Chapter 15 · Cluster & pipeline security

Every earlier chapter ended with a best practice. This one puts them together into a defensible system:

  • least-privilege access for people, pipelines and pods;
  • pods that can't escalate;
  • secrets that never touch Git;
  • a hardened cluster;
  • an Azure DevOps setup where a malicious PR can't reach production.

By the end, you can

  • Write least-privilege Kubernetes RBAC, and combine it with Entra ID groups.
  • Scope the pipeline's identity to only what it deploys.
  • Enforce Pod Security Standards ("restricted") and write a hardened securityContext.
  • Deliver secrets from Key Vault with the Secrets Store CSI driver + workload identity.
  • Harden the cluster: API access, local accounts off, KMS encryption, Defender for Containers, upgrades.
  • Secure Azure DevOps: protected resources and checks, branch control, extends templates, limited service-connection scope.
