Hardening the cluster

You'll be able to review an AKS cluster against a hardening checklist, explain the threat each item addresses, and enable the missing controls.

1. The checklist

2. Enabling the Azure-side controls

az aks update -g rg-orders-prod -n aks-orders-prod \
  --enable-defender \
  --enable-image-cleaner \
  --enable-azure-keyvault-kms --azure-keyvault-kms-key-id "$KMS_KEY_ID" \
  --azure-keyvault-kms-key-vault-network-access Private --azure-keyvault-kms-key-vault-resource-id "$KV_ID"
az aks enable-addons -g rg-orders-prod -n aks-orders-prod -a azure-policy

In practice, all of these are arguments in the Terraform or Bicep definition (Chapters 12–13), not one-off commands.

3. Find the gaps

A prod cluster review shows the following. Select every gap.

apiServerAccessProfile: { enablePrivateCluster: false, authorizedIPRanges: [] }
disableLocalAccounts: true
aadProfile: { enableAzureRBAC: true }
autoUpgradeProfile: { upgradeChannel: patch, nodeOSUpgradeChannel: None }
securityProfile: { defender: { securityMonitoring: { enabled: false } }, workloadIdentity: { enabled: true } }
addonProfiles: { azurepolicy: { enabled: false } }
namespace orders labels: pod-security.kubernetes.io/warn=restricted
  1. A public API server with no authorized IP ranges
  2. Node OS upgrade channel None (no OS patching)
  3. Defender for Containers off
  4. The Azure Policy add-on off
  5. Pod Security only in warn mode for orders
  6. Local accounts disabled That's correct.
  7. Workload identity enabled That's correct.
Five gaps, each one config line in IaC.

4. Threat → control

Match each threat to the control that addresses it.

A leaked admin kubeconfigLocal accounts disabled
A container escapes to the nodePod Security restricted + patched nodes
A compromised pod scans the network for the databaseDefault-deny NetworkPolicy
Someone deploys an image from Docker HubAn admission policy for allowed registries (Azure Policy / Kyverno)
A crypto-miner starts inside a podDefender for Containers runtime detection
A disk or backup of etcd is stolenKMS etcd encryption with your key
Layers: prevent (identity, policy, network), harden (pod security, patching), detect (Defender), protect data (KMS).

5. Keep up with upgrades

An unsupported Kubernetes version stops getting security fixes. Patch automatically (the patch channel plus node images) and upgrade minor versions regularly (lesson 4.4). Defender flags clusters on outdated versions.

6. Defender for Containers

  • Vulnerability assessment of images in ACR and running images.
  • Runtime threat detection on nodes: suspicious processes, crypto-mining, privilege escalation.
  • Posture recommendations that map to this checklist.

Alerts go to Defender for Cloud and can trigger your incident process.

7. Secure score as a tracker

Defender for Cloud's recommendations for each cluster form a to-do list. Contoso reviews them monthly, fixes them in IaC, and treats a new high-severity recommendation like a bug.

8. Node access

Nobody should SSH to nodes routinely. Disable SSH access on node pools where supported, and use kubectl debug node/… for rare investigations. That's audited, and needs explicit RBAC.

9. Encode the baseline

Put every checklist item into the Terraform or Bicep cluster module (lesson 12.6), and add Azure Policy at the subscription level to audit or deny clusters that don't comply. Then a new cluster is hardened by default.

Hardening, sorted

  • Restrict API access; Entra ID + RBAC; no local accounts.
  • KMS encryption, node OS patching, regular upgrades.
  • Defender for Containers, the Azure Policy add-on, image cleaner.
  • Pod Security enforce, default-deny networking, workload identity.
  • Encode it in IaC and audit with Azure Policy.
