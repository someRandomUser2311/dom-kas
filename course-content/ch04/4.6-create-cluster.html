Creating a cluster

You'll be able to write an az aks create command for a production-shaped baseline cluster, and explain every flag in it.

1. Start from the smallest command

This works, but every important decision is left to defaults. Over the next steps we'll add one decision at a time.

In real projects this becomes Terraform or Bicep (Chapters 12–13). The settings are the same; only the syntax changes.

az group create --name rg-orders-dev --location westeurope

az aks create \
  --resource-group rg-orders-dev \
  --name aks-orders-dev
Windows/IIS admin
Think of it as a scripted server build: every flag is a checkbox you'd otherwise click in a wizard, but now it's repeatable.
Linux admin
It's one long command; keep it in a script under version control, not in shell history.
Developer (Compose)
Like a very long docker run, except it creates infrastructure for 5–10 minutes.
Other clouds
The equivalent of eksctl create cluster or gcloud container clusters create.

2. Tier, version and the system pool

az aks create \
  --resource-group rg-orders-dev \
  --name aks-orders-dev \
+ --tier standard \
+ --kubernetes-version 1.33 \
+ --nodepool-name system \
+ --node-vm-size Standard_D4ds_v5 \
+ --node-count 3 \
+ --zones 1 2 3 \
+ --nodepool-taints CriticalAddonsOnly=true:NoSchedule

The default pool becomes our tainted system pool: three nodes, one per zone (lesson 4.2). The Standard tier gives the control-plane SLA.

3. Networking: Azure CNI Overlay with Cilium

+ --network-plugin azure \
+ --network-plugin-mode overlay \
+ --network-dataplane cilium \
+ --pod-cidr 192.168.0.0/16

Nodes get VNet IPs; pods get IPs from a separate overlay range, so they don't use up the subnet. Cilium provides fast networking and network policy enforcement.

Chapter 5 explains the options. In Chapter 5 you'll also add --vnet-subnet-id to put the nodes in Contoso's own subnet.

4. Workload identity

Two flags let pods authenticate to Azure services (Key Vault, Storage, SQL) without secrets:

  • the OIDC issuer publishes the cluster's token-signing keys;
  • workload identity installs the webhook that hands pods Azure tokens.

Chapter 5 explains how it works.

Contoso's cluster already exists. Turn on workload identity (and the OIDC issuer it needs) with az aks update.

az aks update -g rg-orders-dev -n aks-orders-dev --enable-oidc-issuer --enable-workload-identity

Also accepted: --resource-group/--name long forms, flags in any order. Both feature flags are required.

Workload identity depends on the OIDC issuer. Once enabled, the issuer can't be turned off.

5. Entra ID and Azure RBAC

These three flags make Entra ID the way humans sign in to the cluster, and Azure RBAC the way their permissions are granted:

  • --enable-aad: users sign in with their Entra ID account (through kubelogin).
  • --enable-azure-rbac: Kubernetes permissions are Azure role assignments, such as "Azure Kubernetes Service RBAC Reader" on a namespace, managed like every other Azure permission.
  • --disable-local-accounts: removes the static admin kubeconfig, so az aks get-credentials --admin stops working. Every access is a named identity.
+ --enable-oidc-issuer \
+ --enable-workload-identity \
+ --enable-aad \
+ --enable-azure-rbac \
+ --disable-local-accounts

6. Upgrades on autopilot

+ --auto-upgrade-channel patch \
+ --node-os-upgrade-channel NodeImage

Patch versions and node images now arrive automatically (lesson 4.4). Add maintenance windows afterwards with az aks maintenanceconfiguration add.

7. Identity of the cluster itself

AKS uses a managed identity for its own work, such as creating load balancers and attaching disks.

For production, create a user-assigned identity first and pass it in. It survives cluster rebuilds, and you can grant it permissions (e.g. on the VNet) before the cluster exists.

The kubelet identity (used to pull images) is separate. Chapter 6 grants it AcrPull.

+ --assign-identity /subscriptions/<sub>/resourceGroups/rg-orders-dev/providers/Microsoft.ManagedIdentity/userAssignedIdentities/id-aks-orders-dev \
+ --node-resource-group rg-orders-dev-nodes \
+ --os-sku AzureLinux

8. Spot the safety flag

Tap the flag that stops anyone from getting a static, all-powerful admin kubeconfig.

az aks create \
  --resource-group rg-orders-dev \
  --name aks-orders-dev \
  --tier standard \
  --enable-aad \
  --enable-azure-rbac \
  --disable-local-accounts \
  --auto-upgrade-channel patch
--disable-local-accounts removes the cluster-admin certificate behind get-credentials --admin. Before turning it on, make sure an Entra ID group has an admin role, or you'll lock yourself out.

9. Add the user pool

Add the pool for apps.

az aks nodepool add -g rg-orders-dev --cluster-name aks-orders-dev \
  --name user --mode ? \
  --node-vm-size Standard_D4ds_v5 --zones 1 2 3 \
  --enable-cluster-autoscaler --min-count 2 --max-count 10
  • User
  • System System pools are for add-ons; this pool is for apps.
  • Spot Spot is a --priority, not a mode.
  • Workload Not a valid mode.
Mode User pools can scale to zero and hold application pods.

11. The full baseline

#!/usr/bin/env bash
set -euo pipefail
RG=rg-orders-dev; NAME=aks-orders-dev; LOC=westeurope

az group create -n "$RG" -l "$LOC"

az aks create -g "$RG" -n "$NAME" \
  --tier standard \
  --kubernetes-version 1.33 \
  --nodepool-name system --node-vm-size Standard_D4ds_v5 --node-count 3 --zones 1 2 3 \
  --nodepool-taints CriticalAddonsOnly=true:NoSchedule \
  --os-sku AzureLinux \
  --network-plugin azure --network-plugin-mode overlay --network-dataplane cilium \
  --pod-cidr 192.168.0.0/16 \
  --enable-oidc-issuer --enable-workload-identity \
  --enable-aad --enable-azure-rbac --disable-local-accounts \
  --auto-upgrade-channel patch --node-os-upgrade-channel NodeImage

az aks nodepool add -g "$RG" --cluster-name "$NAME" -n user --mode User \
  --node-vm-size Standard_D4ds_v5 --zones 1 2 3 \
  --enable-cluster-autoscaler --min-count 2 --max-count 10

Creating a cluster, sorted

  • Standard tier, zones 1 2 3, and a tainted system pool plus an autoscaled user pool.
  • Azure CNI Overlay + Cilium.
  • OIDC issuer + workload identity for secretless pod access to Azure.
  • Entra ID + Azure RBAC + local accounts disabled.
  • Patch and NodeImage channels for automatic updates.
