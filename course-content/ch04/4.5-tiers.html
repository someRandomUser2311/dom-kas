Tiers, SKUs & AKS Automatic

You'll be able to pick the right AKS pricing tier for each environment, explain what AKS Automatic decides for you, and name the main cost drivers.

1. Three pricing tiers

The tier is about the control plane. You always pay separately for nodes, disks and networking.

TierControl planeGood for
FreeNo charge, no uptime SLA, intended for smaller clustersLearning, dev, experiments
StandardHourly charge per cluster; financially backed uptime SLA (higher with availability zones); scales to large clustersProduction
PremiumEverything in Standard, plus long-term support (LTS) versionsProduction that must stay on one version for longer

Change the tier at any time with az aks update --tier standard.

3. Production needs an SLA

Contoso's production cluster must have a financially backed control-plane uptime SLA. What's the minimum?

  1. Free with three zones Zones protect nodes, but Free has no control-plane SLA at all.
  2. Standard tier (with availability zones for the higher SLA)
  3. Premium only Premium includes the SLA, but Standard is enough unless you need LTS.
  4. Any tier; AKS always has an SLA The SLA only comes with the paid tiers.
The SLA covers the API server. Your app's availability still depends on replicas, zones and PDBs.

4. AKS Automatic

AKS Automatic is a way of creating a cluster where Azure makes most choices for you, following its own best practices. You mainly bring workloads.

It comes preconfigured with:

  • Node Auto Provisioning: no node pools to design;
  • automatic upgrades and node patching, with maintenance windows;
  • Azure CNI Overlay with Cilium;
  • Entra ID + Azure RBAC, with local accounts disabled;
  • workload identity;
  • monitoring;
  • deployment safeguards that enforce good manifests (probes, resource requests, and so on).

The alternative is AKS Standard (the cluster type, not the pricing tier), where you choose all of this yourself.

5. What you give up with Automatic

  • Less control: you can't design node pools freely, and some settings are fixed.
  • Some features and add-ons may not be supported yet. Check the current docs.
  • Safeguards may reject manifests that work elsewhere until you fix them. That's a good thing, but it surprises people.

This course uses AKS Standard so you see and understand every choice. Every setting Automatic picks is one you'll configure yourself in Chapters 4–6 and 12–13.

6. What drives the bill

  • Nodes: by far the largest cost. Right-size requests, use the autoscaler, and consider spot for batch work and reservations or savings plans for steady load.
  • The control-plane tier (Standard/Premium).
  • Disks (OS disks, PVs), load balancers and public IPs.
  • Egress data and NAT gateways.
  • Monitoring ingestion (Log Analytics), which is often a surprise. Chapter 14 covers how to keep it in check.

AKS cost analysis (an add-on) breaks costs down by namespace, so teams can see their own spend.

7. Cheaper dev clusters

  • The Free tier.
  • az aks stop and az aks start to shut a whole cluster down outside working hours; you pay nothing for its nodes while stopped.
  • Smaller VM sizes and a lower autoscaler min.
  • A spot user pool.

Tiers, sorted

  • Free (no SLA) for dev; Standard (SLA) for production; Premium adds LTS.
  • AKS Automatic = Azure's opinionated defaults and safeguards; AKS Standard = you choose.
  • Nodes dominate cost; watch disks, IPs, egress and log ingestion too.
