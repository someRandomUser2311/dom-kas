  1. Brief downtime, then it continues
  2. The drain is blocked; the upgrade waits and eventually fails (drain timeout)
  3. The PDB is ignored
  4. The pod is upgraded in place

  1. A 6th node is added
  2. 4 pods stay Pending with "max node group size reached"

  4. Existing pods are evicted

Write lab: create-cluster.sh

Brief: Write create-cluster.sh for Contoso's dev cluster aks-orders-dev in rg-orders-dev (westeurope). Graded by cli-spec: each command is parsed into verb and flags, so flag order and long/short forms don't matter.

  • The script starts with set -euo pipefail.
  • az group create for the resource group.
  • az aks create with --tier standard.
  • The system pool spans --zones 1 2 3 with at least 2 nodes.
  • --network-plugin azure and --network-plugin-mode overlay.
  • --enable-oidc-issuer and --enable-workload-identity.
  • --enable-aad and --enable-azure-rbac.
  • --disable-local-accounts.
  • An --auto-upgrade-channel other than none, and a --node-os-upgrade-channel other than None.
  • az aks nodepool add with --mode User, zones 1 2 3 and the cluster autoscaler enabled.

The full script in lesson 4.6, step 11.

Walkthrough: create → get-credentials → nodes → upgrade

  1. Run the baseline script; follow az aks create progress (~6–10 minutes).
  2. Look at the two resource groups in the portal: rg-orders-dev and the node resource group.
  3. az aks get-credentials, then kubelogin convert-kubeconfig -l azurecli; kubectl get nodes with pool and zone columns.
  4. kubectl get pods -n kube-system: no control-plane pods.
  5. az aks get-upgrades, then a node-image upgrade of the user pool while kubectl get nodes -w shows surge, cordon and drain.

Try it locally

Most of this chapter is Azure-only. These two boxes rehearse the Kubernetes side on the kind lab.

4.2 Fake node pools.

kubectl label node kq-worker kq-worker2 pool=user
kubectl taint node kq-worker3 CriticalAddonsOnly=true:NoSchedule; kubectl label node kq-worker3 pool=system
kubectl create deployment web --image=localhost:5001/orders-api:1.0.0 --replicas=4
kubectl get pods -o wide

Expected: no web pod lands on kq-worker3 (it doesn't tolerate the taint), and none on the GPU node.

Cleanup: kubectl delete deploy web; kubectl taint node kq-worker3 CriticalAddonsOnly-; kubectl label node kq-worker kq-worker2 kq-worker3 pool-

4.4 Rehearse a node upgrade.

kubectl apply -f lab/examples/ch04/upgrade-demo.yaml     # 3 replicas + PDB maxUnavailable 1
kubectl cordon kq-worker
kubectl drain kq-worker --ignore-daemonsets --delete-emptydir-data
kubectl get pods -o wide

Expected: pods evicted one at a time and recreated on other workers. This is exactly what AKS does to each node during an upgrade.

Cleanup: kubectl uncordon kq-worker; kubectl delete -f lab/examples/ch04/upgrade-demo.yaml
