Agents and agent pools

⏱ 14 min·Agent matcher simulation·2 knowledge checks

Your YAML is only instructions. Something has to execute them: clone the repo, run npm test, call docker build. That something is an agent: a small program (the Azure Pipelines agent) running on a VM or container that polls Azure DevOps for work.

Agents are grouped into agent pools. A job asks for a pool (pool:), and Azure DevOps hands the job to any free agent in that pool that meets the job's demands.

Microsoft-hosted vs self-hosted

Pros
  • Zero maintenance: a fresh, patched VM per job
  • Lots of tools preinstalled (Docker, kubectl, Azure CLI, Helm, Node…)
  • Clean environment every time, no leftover state
Cons
  • Runs on the public internet, so it can't reach a private AKS API server or private ACR
  • No cache between runs (slower Docker builds)
  • Time limits per job, and limited parallel jobs on the free tier
Pros
  • Runs inside your network/VNet, so it can reach private AKS, private ACR and on-prem systems
  • Warm caches and faster builds
  • Any tools or hardware you need
Cons
  • You patch the OS, update the agent and secure it
  • State leaks between jobs unless you clean up
  • A compromised agent is inside your network, so treat it as a sensitive host

The middle ground: Azure-managed scaling of self-hosted-style agents, with VMs created in your subscription and VNet and recycled after each job.

  • Managed DevOps Pools: the current recommended option. Azure runs the pool, you choose the image, size and VNet.
  • VM Scale Set agents: the older approach; you own the scale set and Azure DevOps scales it.
  • Both give you private network access + fresh machines, ideal for deploying to private AKS.

How a job finds an agent: demands & capabilities

Every agent advertises capabilities (its OS, installed tools, custom tags). A job can list demands. Only agents that satisfy every demand are eligible. Toggle the demands and dispatch the job.

Pool: linux-builders · 3 agents

Parallel jobs = how many jobs run at once across your organization. With one parallel job, a second pipeline run queues even if you have ten idle self-hosted agents. Capacity is purchased (or granted on the free tier) separately for Microsoft-hosted and self-hosted.
